# Virtual Persona Core

[English](README.md) · **Русский**

Платформа для «живых» персонажей: ботов, которые помнят собеседника, живут своей жизнью
между сообщениями и сами пишут первыми. Персона — это YAML-файл с характером, памятью и
набором модулей. Одна и та же персона работает в Telegram, в веб-интерфейсе и в приложении
на телефоне, умеет напоминать, вести дела и учить, а по просьбе владельца — управлять его
браузером.

Отвечает любая OpenAI-совместимая модель по API-ключу, веб-чат LLM в браузере бота
(DeepSeek, Qwen, Claude, ChatGPT и др.) или локальная модель в Ollama — то есть бот может
обойтись вообще без ключей.

Бэкенд — Python (FastAPI, ChromaDB, python-telegram-bot), веб — React (`web/`), панель в
трее — Tauri (`desktop/`). Основная платформа — macOS; Windows поддерживается, но проверен
меньше.

## Что умеет

- **Telegram, веб и телефон.** В Telegram — личные сообщения и группы (по слову-триггеру или
  ответу на сообщение бота), команды, длинный код уходит файлами. В вебе — чаты со всеми
  персонами, досье, комната персоны, настройки, редактор персон, голосовой режим. На
  Android — приложение с теми же чатами, голосом, камерой и уведомлениями, когда оно закрыто;
  телефон подключается к компьютеру по шифрованному каналу.
- **Память.** Последние сообщения чата, факты о собеседнике (модель извлекает их сама,
  сливает дубликаты и разбирает противоречия), досье чата, дневник самой персоны, файлы
  с поиском по содержимому.
- **Жизнь между сообщениями.** У персоны есть настроение, энергия, занятие и место, свой мир
  с людьми и сюжетами, события, пока вы молчите. Вернувшись, вы услышите, чем она жила.
- **Инициатива и ритм суток.** Персона пишет первой, когда есть повод, и учится, на что вы
  отвечаете. Утром здоровается, ночью гонит спать, предупреждает о дожде.
- **Уровень интеллекта.** Человек отвечает на бытовой вопрос по-человечески, а не простынёй
  ассистента; лесной дух — жестом. Это задаётся уровнем: `primitive`, `normal`, `bot`.
- **Хозяйство.** Напоминания («завтра в 12», «по пятницам в 18:00»), список дел, заметки
  («запиши в заметки …», «что у меня в заметках?» — у каждой персоны свои, видны на главной),
  инвентарь, курсы обучения с тестами, веб-поиск.
- **Сервисы и уведомления.** Gmail и Google Диск, GitHub, ваш Telegram-аккаунт, любая почта
  по IMAP, RSS-ленты и вебхук: персона решает, стоит ли вас отвлекать (ваши правила, признаки
  самого сервиса, локальная модель), и пишет в своём чате, на телефон или в Telegram;
  остальное — в сводку. В чате: «что нового в почте?», «кто мне писал?», «не присылай
  уведомления от Ozon».
- **Режим управления.** По команде владельца бот открывает сайты и приложения, ищет на
  сайтах, нажимает кнопки, вводит текст, читает страницы, выполняет многошаговые задачи
  («закажи пиццу») и повторяет записанные сценарии. Действия — с подтверждением. Шаги
  задач берегут аккаунты веб-чатов: при сбое они идут на сайты без аккаунта (duck.ai,
  Google AI Mode без входа) или на тот, что дольше всех отдыхал, а не на основной.
- **Экран и камера.** «Посмотри на экран» — персона смотрит на экран компьютера; кнопка
  камеры в чате — на снимок с телефона или веб-камеры. Картинку видит только локальная
  модель в Ollama, персоне уходит её описание.
- **Файлы с компьютера.** «Открой файл отчёт по физике», «пришли файл про налоговый вычет» —
  бот находит файл на компьютере, где работает ядро: веб на нём открывает файл, приложению на
  телефоне и Telegram приходит сам файл.
- **Лор персонажа.** История и мир отдельным файлом вместо длинного промпта: на каждую реплику
  персона получает только нужные куски. Без лишних токенов и без лишних вызовов модели.
- **Голосовая активация.** Назовите персону — «Коннор, какая погода?» — и она ответит вслух:
  на компьютере, где работает ядро, и на телефоне, даже с погашенным экраном. Команды телефону —
  тоже голосом: «Коннор, включи фонарик».
- **Без ключей.** Веб-чаты LLM в браузере бота или локальная модель в Ollama.
- **Аддоны.** Пример — Арродес: персона-знаток книги с гибридным поиском по её тексту.

## Быстрый старт

Нужны Python 3.11+, для веба — Node.js 20.19+ или 22.12+. Для веб-чатов и режима управления —
браузер на Chromium (Chrome, Edge, Brave, Opera, Яндекс, Vivaldi). Ollama — по желанию.
`requirements.txt` ставит точные проверенные версии пакетов на Linux, Windows и macOS 14+
с Apple Silicon. На Intel-маках и macOS 13 у этих версий torch и onnxruntime нет сборок.

```bash
git clone <repo-url> virtual-persona-core
cd virtual-persona-core

python3 -m venv .venv
source .venv/bin/activate                    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -e .

cp .env.example .env                         # пустой шаблон личных настроек
python -m app.main api                       # бэкенд: http://127.0.0.1:8000
```

Во втором терминале — веб-интерфейс:

```bash
cd web
npm ci
npm run dev                                  # http://localhost:5173
```

На чистой установке ничего не выбрано за вас: нет ни ключей, ни основного провайдера, ни
моделей, а из персон есть только тестовый Коннор. Откройте в вебе «Настройки», добавьте
ключ провайдера и впишите модель — без модели провайдер не используется. То же можно
задать в `.env`: `<ПРОВАЙДЕР>_API_KEY` и `<ПРОВАЙДЕР>_MODEL`.

**Telegram.** Создайте бота у [@BotFather](https://t.me/BotFather), впишите токен в `.env`
как `<ПЕРСОНА>_BOT_TOKEN` (например, `CONNOR_BOT_TOKEN`) и запустите
`python -m app.main connor` или `python -m app.main all`.

**Панель в трее** (macOS и Windows) запускает, перезапускает и останавливает бэкенд и веб,
показывает их состояние и живой лог и слушает имена персон своим микрофоном
([Голосовая активация](#голосовая-активация)). Ещё она держит живой портрет персоны на рабочем
столе — голова поверх всех окон, без рамки и фона: смотрит на курсор, её можно погладить
кликом, реплики персоны всплывают облачком над головой (слово за словом, длинные — по
частям, пока не договорит; клик по последней — чат), в поле сбоку от головы (появляется, когда наводишь на персонажа) можно написать ей, засыпает, когда вас
нет или персона спит (погладили — просыпается на 5 минут), а клики рядом с ней проходят к окнам
под ней. Его можно схватить и бросить, он сам гуляет по экрану и по верхним краям окон,
играет свои анимации из раздела «Аватар», а брошенный на него файл персона прочитает и
ответит; правой кнопкой — «Иди сюда», «Спрячься», «Посиди со мной». Сборка — в
[desktop/README.md](desktop/README.md).

**Docker** — `docker compose up -d --build`, подробности в разделе [Docker](#docker).

## Настройки

Секреты и личные настройки — в `.env` (не в git). Несекретные значения по умолчанию —
в `.env.config` (в git). Значение из `.env` важнее, переменная окружения процесса — ещё
важнее. Многое меняется из веба: в «Настройках» — ключи провайдеров, часовой пояс,
местоположение; в досье персоны — её модули.

Для ответов нужен хотя бы один источник: провайдер с ключом и моделью, веб-чат или Ollama
с выбранной и скачанной моделью. Моделей по умолчанию нет — их выбирает человек.

| Переменная | Что задаёт |
|---|---|
| `<ПРОВАЙДЕР>_API_KEY` | ключ провайдера: `ZAI`, `OPENAI`, `ANTHROPIC`, `GROQ`, `DEEPSEEK`, `KIMI`, `GOOGLE`, `MIMO`, `HF`. Запасные ключи — `_API_KEY_1`, `_API_KEY_2`… |
| `<ПРОВАЙДЕР>_MODEL` | модель провайдера; без неё провайдер не используется |
| `ACTIVE_PROVIDER` | основной провайдер; пусто или без ключа — первый провайдер с ключом и моделью |
| `<ПЕРСОНА>_BOT_TOKEN` | токен Telegram-бота персоны (имя YAML-файла заглавными) |
| `OWNER_USER_ID` | Telegram ID владельца: команды владельца и режим управления |
| `TIMEZONE` | часовой пояс пользователя (IANA, например `Europe/Moscow`); пусто — системный |
| `WEBCHAT_SITES` | веб-чаты по порядку, например `deepseek,qwen` |
| `WEBCHAT_LENGTH_HINT` | веб-чату лимит токенов числом не передать — лимит 40–1200 токенов уходит в промпт словами («не больше ~200 слов, примерно 8–17 предложений» для 400 токенов по-русски); `0` — выключить |
| `OLLAMA_URL`, `OLLAMA_MODEL` | локальная модель: адрес (`http://localhost:11434`) и модель, например `gemma4:e2b` |
| `LOCAL_LLM_BACKEND` | кто делает служебную работу (классификации, извлечение): `ollama` или `webchat` |
| `LOCAL_LLM_DEVICE` | где работает то, что шло бы в Ollama: `pc` (по умолчанию) или `phone` — Gemma приложения на телефоне берёт задачи на пути ответа и основной ответ при откате на локальную модель; фоновые задачи, картинки и приватные страницы остаются за Ollama компьютера |
| `LTM_MODEL_PROVIDER` | отдельный провайдер для извлечения фактов; пусто — цепочка персоны |
| `API_HOST`, `API_PORT` | адрес бэкенда: `127.0.0.1:8000` |
| `API_TOKEN` | пароль к API для сети (телефон по адресу, Pi, другой компьютер); с этой машины не нужен. Пусто — без пароля, но только для этой машины |
| `API_TOKEN_LOCAL` | `1` — токен и с этой машины (компьютер с другими учётными записями) |
| `API_CORS_ORIGINS`, `API_ALLOWED_HOSTS` | чьим страницам и по каким именам хоста можно в API — см. [API](#api) |
| `VPC_DATA_DIR` | папка данных — одна на всё: память, ваши персоны, состояние; по умолчанию `data/`. `DATA_DIR` — прежнее имя той же настройки |
| `RATE_LIMIT_DEFAULT`, `RATE_WINDOW` | лимит сообщений в Telegram (6 за 3600 с) для персон с `rate_limit` |

Остальное — с комментариями в `.env.example`.

### Где лежат данные

Ваши персоны — в `data/personas/`. Память персоны в Telegram — в `data/<персона>/`, в вебе —
в `data/api_<персона>/`: это разные собеседники и разная память. Там же — состояние жизни
персоны, дневник, напоминания, дела, журнал режима управления
(`computer_control/audit.jsonl`). Папка `data/` в git не попадает.

Бэкенд пишет лог в терминал; в вебе его видно в режиме разработчика. Если бота запускает
панель, лог ещё и сохраняется в `logs/` на 14 дней.

## Запуск

```bash
python -m app.main             # меню: персоны с токенами, все боты, API
python -m app.main api         # бэкенд для веба и панели — токены Telegram не нужны
python -m app.main connor      # Telegram-бот одной персоны
python -m app.main all         # Telegram-боты всех персон, у которых есть токен
BOT_TARGET=all python -m app.main
```

Веб и Telegram — разные процессы: можно запускать любой отдельно или оба сразу.

На Windows та же команда сама подключает логику окон браузера бота: окна агента видны
только в режиме управления, остальные стоят за экраном. Выключить — `VPC_WIN_WINDOWS=0`.

### Telegram

В личке бот отвечает на всё. В группе — на ответ на своё сообщение и на сообщение, которое
начинается со слова из `trigger_words` (по умолчанию — id персоны). Сообщения, пришедшие,
пока бот был выключен, пропускаются.

| Команда | Что делает |
|---|---|
| `/start`, `/help` | приветствие и список возможностей; `/start` в личке начинает разговор заново, как `/clear` |
| `/commands` | команды привязанного робота и состояние тела; без обращения к модели и без действий на роботе |
| `/clear` | очистить историю этого чата: переписку и тред веб-чата LLM (в группе — админы) |
| `/stats`, `/last N` | счётчики памяти; последние N сообщений чата |
| `/reset`, `/forget <текст>` | забыть все свои факты; забыть один факт |
| `/relations` | кто с кем в чате |
| `/ratelimits` | состояние лимитов |
| `/ltm_privacy [smart\|strict]`, `/ltm_export` | что запоминать о вас; ваши факты файлом в личку |
| `/web` | веб-поиск в этом чате вкл/выкл (`web_search`) |
| `/todo`, `/add_todo` | список дел (`todo`) |
| `/notes` | мои заметки (`notes`) |
| `/remind`, `/reminders`, `/cancel_reminder` | напоминания (`reminder`) |
| `/inventory`, `/add_inventory` | инвентарь (`inventory`) |
| `/learn <тема>`, `/stop_learning` | курс обучения (`learning`) |
| `/files`, `/reset_files` | загруженные файлы (`file_upload`) |
| `/erase N`, `/context`, `/resetall`, `/reset_diary` | только владельцу: стереть последние N сообщений, контекст промпта файлом, вся память, дневник |

В скобках — модуль персоны, без которого команды нет. Команды проходят те же фильтры, что
и сообщения: блокировки, лимиты, модерацию, заморозку.

### Веб-интерфейс

- **Плеер** — выбор нескольких аудиофайлов и перетаскивание, библиотека с сохранением
  в браузере, перемотка, громкость, очередь и повтор трека. Музыка продолжает играть
  при переходе в другие разделы. Внизу остаётся компактная полоса только активного
  источника с кнопками, перемоткой и громкостью; раскрытие ведёт в полный раздел плеера.
  Можно импортировать файл по полному пути на ПК ядра:
  эта функция доступна из браузера на самом ПК и копирует файл в библиотеку браузера.
  На телефоне используйте выбор файлов. До 100 МБ на трек; поддержка кодеков зависит
  от браузера. Очистка данных сайта удаляет библиотеку, закрытие вкладки останавливает
  воспроизведение локальных файлов. Для новых функций после обновления нужно перезапустить ядро.
  **YouTube / YouTube Music на ПК** — ссылка на видео или плейлист, отдельный Chrome
  без окна или с видимым окном для входа/подтверждений, пауза, продолжение, громкость,
  перемотка и следующий трек. Звук выходит на ПК ядра; управлять можно с этого ПК.
  Профиль плеера хранится в `data/player/chrome-profile` (с учётом `VPC_DATA_DIR`),
  обычные браузеры и браузеры агента не затрагиваются. Закрытие вкладки приложения
  оставляет онлайн-музыку играть; «Закрыть браузер» и остановка ядра завершают Chrome.
  Воспроизведение зависит от доступности YouTube, входа, согласий и ошибок сайта;
  при ошибке можно открыть видимое окно. Встроенный YouTube API и извлечение аудио
  здесь не используются: управляется обычная страница сервиса.
  Для повторения замера нагрузки: `python -m scripts.benchmark_player --seconds 40 --rounds 3`.
  Отчёт — `data/player/benchmarks/latest.json`; CPU 100% означает одно логическое ядро,
  память — сумма RSS процессов Chrome (общие страницы могут учитываться повторно).
  Проверка реального headless-воспроизведения до конца ролика:
  `python -m scripts.test_player_live --url "https://www.youtube.com/watch?v=0WA2NX4kPSI" --seconds 0`.
  Проверка Music с переключением: `python -m scripts.test_player_live --url "https://music.youtube.com/watch?v=dQw4w9WgXcQ" --seconds 150 --next-seconds 90`.
  Проверки используют временные гостевые профили и тихий звук; личные cookies не читаются.
  **Поиск музыки из чата:** в плеере выберите «Где искать музыку» — YouTube или
  YouTube Music. Выбор сохраняется на ядре и используется всеми персонами.
  «Включи Rick Astley Never Gonna Give You Up» сначала ищет MP3 по имени на ПК
  (системный индекс, затем обычные пользовательские папки; бюджет около 1,2 с),
  затем запускает первый видеотрек из поиска выбранного сервиса.
  «Включи песню SAIKAI на YouTube Music» задаёт сервис для этой просьбы;
  «открой SAIKAI на ютубе» сразу ищет онлайн, сохраняя явный смысл «на сайте».
  Найденный MP3 играет в том же плеере на ПК. Команда не требует режима управления;
  она доступна владельцу в личном чате, не исполняется из скинов и не перехватывает
  настройки, звук, субтитры, известные приложения и запись сценариев.
  Отключить у персоны: `features.music_player: false`. Отдельный Telegram-процесс
  передаёт команды своему API, когда оно работает, чтобы веб-плеер управлял тем же браузером.
  **Управление:** «пауза», «продолжи», «следующий трек», «предыдущий», «громче»,
  «тише» работают для MP3 и обоих сервисов; шаг громкости — 10%. MP3 на ПК
  переключаются по имени в той же папке, загруженные файлы — по библиотеке
  (вкладка плеера должна оставаться открытой). На YouTube предыдущий трек
  восстанавливается из истории плеера. Во время задачи или сценария короткие
  команды остаются диалогу; «пауза в плеере» и «продолжи музыку» управляют музыкой.
  Справа от аватара появляется короткий док с кнопками в два столбца: пауза,
  переключение треков и громкость. Как кнопка чата, он скрывается через 3 секунды
  после ухода курсора и возвращается при наведении на персонажа; музыка продолжает
  играть. Во время работы с плеером таймер продлевается. При временном скрытии
  сохраняются вид плеера и размер прозрачного окна: аватар остаётся на месте.
  Стрелка раскрывает его в карточку с обложкой, перемоткой и ползунком громкости.
  Крестик полностью закрывает плеер и останавливает воспроизведение; новая команда
  «включи …» снова открывает док. Окно desktop-портрета расширяется под плеер,
  чат располагается слева; у края монитора аватар сдвигается, чтобы карточка помещалась.
  После окончания одиночного трека плеер полностью закрывается: рекомендации YouTube/YouTube Music и
  следующий загруженный файл автоматически не запускаются. Автопереход — только
  при воспроизведении плейлиста; ручные кнопки следующего/предыдущего трека работают.
  **Ссылки и плейлисты:** найденная по запросу песня автоматически попадает в
  «Сохранённые песни». Можно добавить или перетащить ссылку вручную, указать своё
  название, добавить песню в несколько плейлистов, переименовать списки и менять
  порядок стрелками. Ссылки на одно видео YouTube и YouTube Music объединяются.
  Без указанного названия метаданные обновятся при воспроизведении.
  Библиотека хранится на ядре в `data/player/catalog.json` (с учётом `VPC_DATA_DIR`),
  переживает перезапуск и общая для персонажей. «Включи плейлист Для работы»
  запускает созданный список; кнопки и команды следующего/предыдущего трека идут
  по нему. Автопереход работает и при закрытой вкладке; после последней песни
  плеер полностью закрывается, включая окно музыкального браузера. Во время проигрывания используется снимок порядка
  песен: чтобы применить правки к очереди, запустите плейлист заново.
  Удаление плейлиста оставляет песни в библиотеке; удаление ссылки из библиотеки
  убирает её из всех сохранённых списков. Аудио с сервиса не скачивается.
  Проверка настоящего плейлиста во временном профиле: `python -m scripts.test_music_playlists_live --last youtube_music`
  (или `--last youtube`). Личная библиотека и cookies не используются.
- **Старт** — как пользоваться: с чего начать, спецфункции, телефон, экран и камера,
  шпаргалка режима управления, команды Telegram.
- **Главная** — календарь и лента «пока вас не было»: инициативы, дневник, напоминания.
- **Чат** — все чаты списком, затем чат с персоной, голосовой режим, камера, скины; в режиме
  управления — кнопки ответа, карточка задачи и живое окно браузера агента. Пока ответ
  готовится, живой портрет (на рабочем столе, в виджете телефона, в окне «картинка в
  картинке») показывает ваше сообщение облачком сбоку от головы: персона кивает,
  поворачивается к нему, «читает» строками, потом задумывается; облачко висит до ответа.
  Пока персона думает, вместо «Отправить» — **«Стоп»**: ответ модели по API обрывается сразу,
  веб-чат на сайте допишет, но ответ выбросится; ваше сообщение остаётся в истории. Работу
  агента в режиме управления «Стоп» останавливает так же, как набранное «стоп»: шаг
  доделывается, персона отвечает, на чём остановилась. Enter по-прежнему отправляет —
  сообщение встанет в очередь за ответом.
- **Комната** — живая сцена персоны: где она, чем занята, её вещи; окно «картинка в картинке»
  и арт-мастерская.
- **Аватар** — **живой портрет** персоны: лист 5×5 ракурсов головы (его рисует генератор
  картинок по готовому промпту) превращает её в 2D-витубера — она смотрит в сторону курсора
  или касания, моргает и шевелит губами, пока говорит, её можно погладить касанием или проведя
  по голове; как и комнату, портрет можно вынести в маленькое окно поверх остальных (Chrome,
  Edge), а панель в трее ставит его прямо на рабочий стол. Там же — **анимации** для рабочего
  стола: свои листы кадров с названием (ест, читает, идёт…), которые портрет играет сам время
  от времени и на события (погладили, держат мышью, падает, думает, читает файл), а персона
  может выбрать подходящую к своей реплике; и памятка, что можно делать с портретом на столе.
  Вкладка **«Кадры»** — редактор листов: нарезанные кадры кладутся слоями друг на друга
  (со своей прозрачностью и цветом у каждого, можно мигать ими), сетку можно поправить
  прямо на листе, а кадр, ряд, столбец или весь лист — сдвинуть и отмасштабировать руками или
  подогнать к опорному слою, чтобы голова и фигура не прыгали. У анимаций под холстом полоска
  времени: кадры двигаются по ней мышью, там же общая скорость, повторы и зацикливание.
- **Персоны** — создание (форма и YAML рядом), правка YAML, переименование, копия, цвет.
- **Скины** — оформление чата, досье и комнаты: библиотека (с шестью встроенными плоскими скинами:
  Тушь, Бланк, Пиксель, Нетраннер, Ретрофутуризм, Метро), загрузка, генерация моделью ядра и
  «Промпт для своей нейросети» — готовый промпт генератора, чтобы сделать скин в любом чат-боте
  самому и загрузить ответ (работает и без ядра). Промпт совпадает с ядром:
  `python -m scripts.gen_skin_prompts` (`--check` — сверка).
- **Настройки** — язык (ru/en), уведомления, режим разработчика, местоположение, часовой
  пояс, ключи провайдеров, веб-чаты.
- **Подключение** — на компьютере: подключить телефон по QR-коду, сопряжённые телефоны и токен
  API для подключения по адресу; в приложении на телефоне: связь с ядром сейчас, ядра в этой
  сети («кто тут ядро?»), уведомления при закрытом приложении и «Слушать по имени».
- **Досье персоны** — память, напоминания и дела, инициатива, режим управления, обучение,
  файлы, настройки персоны (модели, генерация, модули).

Веб ищет бэкенд по `VITE_API_URL` (по умолчанию `http://127.0.0.1:8000`). Веб, открытый на
той же машине, что и бэкенд, токен не спрашивает; открытый с другой машины при заданном
`API_TOKEN` спросит его при входе. Без бэкенда через 3 секунды можно продолжить на
демо-данных — интерфейс сам переключится на живые, когда бэкенд появится.

### Приложение на телефоне (Android)

Веб-интерфейс собирается и как приложение для Android. Бэкенд работает на компьютере,
телефон подключается к нему: те же чаты и история, голос и камера, режим управления с живым
окном браузера, досье и настройки персон. Фоновые сообщения (напоминания, инициатива) доходят до
каждого устройства — и компьютер, и телефон получают свою копию.

**Команды телефону.** В чате приложения (текстом или голосом) и по имени персоны
([Голосовая активация](#голосовая-активация)): «поставь будильник на 7 по
будням», «разбуди меня через 20 минут», «таймер на 10 минут», «покажи будильники», «открой
Telegram», «включи фонарик» — и по-английски. Выполняет сам телефон: будильник и таймер
встают в системные «Часы», приложение открывается по названию. Персона отвечает по итогу и
честно скажет, если не вышло (например, приложения нет или часы не берут дату). Удалять и
выключать будильники телефон не умеет — откроет их список. В режиме управления команды, как
и раньше, адресованы компьютеру; реплику со словами «на компьютере» телефон тоже не трогает.
Работает и без связи с ядром.

**Управление экраном.** Персона нажимает, вводит текст и листает в любом приложении на
телефоне — по просьбе из любого чата: в приложении, в Telegram, на компьютере, голосом.
Обращение к телефону — явное: «на телефоне нажми «Отправить»», «телефон, назад», «на
телефоне домой», «на телефоне листай вниз», «что на экране телефона?», «на телефоне введи
«котики» в поле поиска», «открой на телефоне Telegram», «на телефоне открой шторку» — и
по-английски («tap Send on my phone», «what's on my phone screen?»). Решает ядро, телефон
только исполняет: служба спец. возможностей держит связь с ядром как его устройство, и без
связи с ядром управление экраном не работает. Включается в настройках Android: «Спец.
возможности» → «Virtual Persona: управление экраном»; в приложении — карточка «Управление
экраном» в «Настройках» (состояние, переход в настройки Android, «Что видит ядро»). Android
13+ для приложений не из магазина сначала прячет переключатель: «О приложении» → ⋮ →
«Разрешить ограниченные настройки». Необратимое — «Отправить», «Удалить», «Подтвердить» —
только после вашего «да»; оплату и «Купить» не нажимает никогда; банковские приложения,
пароли и коды входа не читает и не трогает (там работают только «назад» и «домой»), коды из
уведомлений персоне не показываются. Только владелец и не в группах Telegram. По VPC Link
пока не работает — только по адресу ядра.

**Виджеты на рабочем столе.** «Инициатива персон» — последние сообщения, которые персоны
пишут сами (самоинициатива, утро, ночь и погода; напоминаний и уведомлений сервисов там нет),
тап открывает чат. «Комната персоны» — комната выбранной персоны из её арта, целиком, и
сама персона на своём месте и в своей позе, под картинкой — чем она занята; тап открывает
комнату. «Живой портрет» — голова персоны из её живого портрета прямо на обоях: моргает,
поглядывает по сторонам, а когда персона пишет, шевелит губами и «говорит» реплику в облачке
над головой: слово за словом, длинную — частями (скорость слов и смены частей — «Настройки» →
«Общие», одна для портрета на столе и виджета; облачко лежит поверх, голова не сжимается;
экран выключен или заблокирован — реплика ждёт, пока его разблокируют; тап по облачку — чат); тап по голове — погладить; спит персона (или ночь, если ядро этого не
знает) — спит и портрет, без анимации, а погладили — просыпается на 5 минут после последнего
касания. Карандаш в углу портрета — окно «Написать» поверх рабочего стола: поле над
клавиатурой и микрофон (надиктовать); отправили — портрет кивает, думает и отвечает облачком,
переписка та же, что в приложении; команды телефону («поставь таймер на 5 минут») работают и
отсюда; ядро не отвечает — реплика уходит приложению, как в чате без связи. Данные виджеты получают через фоновую связь
(«Уведомления, когда приложение закрыто», только по адресу и токену); комната обновляется,
пока экран включён, портрет при включении экрана проверяет, не спит ли персона.

**Подключение — VPC Link.** Телефон и компьютер один раз знакомятся по QR-коду и дальше
узнают друг друга по ключам: без VPN на телефоне, без аккаунтов и паролей. Всё шифруется из
конца в конец ([Noise](https://noiseprotocol.org), то же семейство протоколов, что у
WireGuard), а само API остаётся на `127.0.0.1` — канал только доносит до него запросы.

1. На компьютере: «Подключение» → **«Подключить телефон»**. Появится одноразовый
   QR-код (действует 10 минут).
2. В приложении: **«Сканировать QR-код»**. Готово — телефон появится в списке на
   компьютере, оттуда его можно отвязать.

Пути связи, по порядку:

- **та же сеть Wi-Fi** — напрямую, порт `LINK_PORT` (8766). Если на macOS включён
  файрвол, разрешите Python входящие подключения;
- **вне дома** — через посредника: крошечный сервер (`app/link/relay.py`, один файл,
  нужен `pip install websockets`) на любой машине, до которой достают оба устройства. Он
  только пересылает шифр: ни прочитать, ни подделать ничего не может. На сервере:
  `python3 relay.py --port 8443 --host-key <пароль>` (за nginx/caddy с TLS или с
  `--cert`/`--key`); в `.env` ядра: `LINK_RELAY_URL=wss://<сервер>` и
  `LINK_RELAY_KEY=<пароль>`. Без посредника телефон работает только в одной сети Wi-Fi.

Компьютер не должен засыпать, пока вы пользуетесь приложением.

**Подключение по адресу** (запасной вариант): `API_HOST=0.0.0.0`,
`API_ALLOWED_HOSTS=192.168.1.5` (адрес компьютера), `API_TOKEN`; в приложении —
`192.168.1.5:8000` и токен. Токен видно на компьютере: «Подключение» → «Токен
API», кнопки «Показать» и «Скопировать». Порт в адресе — порт API (`API_PORT`, 8000), а не
`LINK_PORT`: тот нужен только VPC Link. Трафик здесь не шифруется, поэтому VPC Link лучше.
Без `API_TOKEN` бэкенд отклоняет запросы не с этой машины (403). Если задан
`API_CORS_ORIGINS`, добавьте в него `https://localhost` — это источник приложения.

**Сборка APK** — нужен Android Studio (он ставит Android SDK и Java):

```bash
scripts/fetch_wake_model.sh   # один раз: распознаватель для голосовой активации (~80 МБ, не в git)
cd web
npm ci
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"  # macOS
export ANDROID_HOME="$HOME/Library/Android/sdk"
npm run apk
```

Файл — `web/android/app/build/outputs/apk/debug/app-debug.apk`: скопируйте на телефон и
установите (разрешите установку из этого источника) или поставьте через `adb install`. На
Windows последний шаг — `cd web/android && gradlew assembleDebug` после `npm run build`,
`npm run phone-voice` и `npx cap sync android`.

**Уведомления, когда приложение закрыто** (пока только при подключении по адресу):
«Подключение» → **«Уведомления, когда приложение закрыто»**. Приложение
держит небольшую фоновую службу (тихое уведомление «Связь с ядром» в шторке). Служба держит
открытым запрос к ядру (`GET /api/inbox` с `wait`): ядро отвечает, как только появилось
сообщение, а без сообщений — пустым ответом раз в 5 минут, и служба сразу открывает новый
запрос. Службе со значком в шторке Android не отключает сеть и в глубоком сне, а пришедший
ответ будит телефон, поэтому напоминания и сообщения персон приходят за секунды; тап
открывает чат персоны. Ответ, потерянный по дороге, ядро пришлёт ещё раз.

В шторке видно время последнего ответа: «Подключено к … · ответ ядра в 23:58». Если время
старше 6 минут — связь застряла. Кнопка «Проверить» в «Настройках» приложения показывает
настоящее уведомление Android. Google/Firebase не нужен — работает, пока телефон достаёт до
компьютера; без связи служба повторяет попытки до раза в минуту, во сне — реже. На телефонах
Honor, Huawei и Xiaomi разрешите приложению работу в фоне и выберите «Не ограничивать» в
настройках батареи — иначе система его усыпит. По VPC Link переключатель пока скрыт.

**Камера.** Кнопка с фотоаппаратом рядом с «+» в чате открывает камеру телефона (Android
спросит разрешение). Снимок уменьшается и уходит в ядро, смотрит его только локальная модель —
см. [Экран и камера](#экран-и-камера).

**Голосовой режим** в приложении работает через распознавание речи и озвучку самого Android
(в WebView нет Web Speech API): на телефоне нужна служба распознавания речи — обычно приложение
Google («Голосовой ввод Google»), подойдёт и другой движок — и движок синтеза речи (обычно
«Синтезатор речи Google»). При первом нажатии на микрофон приложение спросит разрешение на
запись звука. Без службы распознавания остаётся ввод текстом, персона всё так же отвечает
голосом; без синтезатора — ответы только текстом. Язык речи — язык интерфейса (русский или
английский); для распознавания без интернета скачайте нужный язык в настройках голосового
ввода телефона.

**Без связи с ядром.** Когда телефон не достаёт до компьютера, приложение отвечает само:
облачной моделью, если ключи API персоны скопированы на телефон, потом веб-чатами без ключей,
иначе — Gemma, скачанной на телефон. Всё это — во вкладке «Провайдеры», которая появляется в меню
только без связи с ядром. Описание персоны, факты и свежую переписку оно
берёт с ядра заранее; разговор хранится на телефоне и уходит в историю ядра, когда связь
вернётся. Новую персону тоже можно создать на телефоне: форма та же, отвечает ей Gemma по её
полному описанию, а на ядро она переезжает при первой связи — под новым id с суффиксом `_2`,
если такой там занят. Дальше это обычная персона: ядро составит ей краткое описание для Gemma,
выдаст ключи API и так далее.

**Без компьютера вовсе.** Если ядра нет, на экране подключения есть кнопка «Пользоваться без
компьютера». Приложение открывается со встроенным Коннором, можно создать свою персону. Отвечает
облачная модель по ключам, введённым на телефоне («Провайдеры» → «Ключи облачных моделей на
телефоне»: ключ и модель, хранятся зашифрованными), потом веб-чаты без ключей, иначе — Gemma на
телефоне.

**Веб-чаты без ключей на телефоне.** Во вкладке «Провайдеры» можно включить сайты чатов: Duck.ai,
ChatGPT и Google AI Mode — без входа, DeepSeek — со входом почтой и паролем. Приложение открывает
сайт невидимым WebView, вводит вопрос и читает ответ со страницы, как веб-чаты ядра; работает и в
фоне, и с погашенным экраном. Промпт тот же, что у облачной модели; в поле Google AI Mode он не
влезает — туда идёт краткий, как для Gemma. Куки и входы сайтов лежат в отдельном профиле WebView
(«Сбросить веб-чаты» стирает только их). Вход и капчу человек проходит сам — вкладкой сайта на весь
экран. У DeepSeek каждая персона пишет в свой чат, новых чатов — не больше шести в день, чтобы сайт
не заблокировал аккаунт. По умолчанию все сайты выключены: переписка уходит на сайт, только если
его включить. Напоминания, поиск,
время, погода (город — в «Настройках»), память переписки и заметки на главной работают без
компьютера. Правила и заметки для этого вшиты в приложение (`web/src/offline/baseKit.ts`,
генерирует `python -m scripts.gen_offline_base_kit` из ядра). Поставили ядро —
«Подключение» → «Подключить компьютер». При первой связи на компьютер переезжают персоны,
переписка (факты из неё ядро извлечёт само), напоминания, заметки и город; Коннор с телефона
ложится в Коннора ядра. Ключи — после вопроса: они добавляются к ключам `.env`, ничего не
заменяя. Дальше главное — компьютер, а без связи с ним телефон снова отвечает сам.

Без компьютера работают и **сервисы**: RSS-ленты, GitHub, почта по IMAP и Gmail (вход Google
своим OAuth-клиентом, как у ядра) — телефон проверяет их сам в фоне раз в 15–30 минут, разбирает
правилами без модели и присылает сообщение персоны (уведомлением и в чат). Google Диск, вебхук
и Telegram-аккаунт — только с компьютером. Подключили компьютер — телефон спросит, перенести ли
сервисы туда (с курсорами, чтобы ядро не прислало уже показанное), и перестанет их проверять сам.
«Запиши в заметки …», «удали заметку 2», «что у меня в заметках?» в чате и голосовая
активация («Коннор, …») тоже работают без компьютера.

## Персоны

В проекте одна встроенная персона — тестовый **Коннор** (`app/personas/connor.yaml`): андроид
RK800, ассистент студентов, уровень `bot`, с режимом управления. Без своих провайдеров и
моделей — отвечает тем, что выбрано в «Настройках». Аддон Арродеса (отдельный репозиторий)
добавляет персону `arrodes`.

Ваши персоны живут в `data/personas/` и в git не попадают. Персона там с тем же id, что у
встроенной, перекрывает встроенную.

Язык ответа следует за языком собеседника, язык фоновых сообщений — за языком
`system_prompt`.

### Как создать персону

- **В вебе:** «Персоны» → «Создать». Форма слева, итоговый YAML справа.
- **Файлом:** положите `<id>.yaml` в `data/personas/`. Веб увидит его сразу, Telegram-боту
  нужны токен `<ID>_BOT_TOKEN` и перезапуск.

Персона — любой YAML с непустым `system_prompt`. id — имя файла: латиница, цифры, `_` и `-`,
до 64 символов. Заняты: `tg`, `default`, `skins`, `skin_gen`, `settings_probe`,
`persona_drafts`, `personas` и всё, что начинается с `api_`.

Всё, что меняется из веба, пишется в `data/personas/`. Первая правка встроенной персоны
создаёт там её копию — файл в `app/personas/` не меняется. Удалить встроенную персону нельзя
(можно заморозить или скопировать); удаление копии сбрасывает персону к встроенной версии.

Правки применяются к веб-боту сразу, кроме нескольких ключей — про них веб скажет, что нужен
перезапуск. Telegram-бот — отдельный процесс: сразу он видит только заморозку (`muted`),
остальное — после перезапуска.

### YAML персоны

```yaml
id: helper
name: Помощник
description: Вежливый ассистент
color: '#38b6a5'                 # цвет в вебе; без него — из палитры по id
stm_size: 50                     # сколько последних сообщений чата помнить дословно

system_prompt: |
  Ты — полезный ассистент. Отвечай кратко и по существу.

settings:
  temperature: 0.7
  max_tokens: 2000
  top_p: 0.9

intellect:
  tier: bot                      # primitive | normal | bot

features:
  trigger_words: [помощник, helper]   # слова-триггеры в группах, строчными буквами
  web_search: true
  file_upload: true
  self_memory: true              # дневник персоны
  todo: true
  reminder: true
  inventory: true
  learning: true
  proactive: true                # инициатива
  rhythm: true                   # утро, ночь, погода
  life: true                     # жизнь между сообщениями

llm:
  primary: groq                  # провайдер, local, webchat или webchat:<сайт>
  fallback: [deepseek, local]
```

Без `features` у персоны остаются разговор и память. Ключи верхнего уровня:

| Ключ | Что задаёт |
|---|---|
| `id`, `name`, `description`, `color` | имя, описание, цвет в вебе |
| `system_prompt` | характер — единственное обязательное поле |
| `settings` | `temperature`, `max_tokens`, `top_p`, `split_messages` (ответ несколькими сообщениями) |
| `stm_size` | размер буфера последних сообщений; по умолчанию `STM_SIZE` из `.env.config` |
| `special_users` | особые собеседники: `id` (можно `${ПЕРЕМЕННАЯ}`), `aliases`, `greeting`, `behavior` |
| `short_prompt` | краткое описание для Gemma телефона; без него ядро составит его само. Его же задаёт окно краткого описания персоны: вставить своё (там же промпт, чтобы скопировать в любую нейросеть) или «Составить заново» моделью персоны |
| `intellect` | уровень интеллекта — см. ниже |
| `conversation_style` | частота вопросов в конце ответа — см. ниже |
| `llm` | модели персоны — см. [Модели](#модели) |
| `world_binding` | `real_world` или `fictional_universe`; без ключа модель определит сама по `system_prompt` |
| `room` | вещи, питомец и места в комнате персоны |
| `start_greeting`, `pre_reply_text` | Telegram: текст на `/start` (`{name}` — имя собеседника); фраза перед долгим ответом |
| `max_docs`, `max_file_size_mb` | лимиты загруженных файлов: 3 документа, 10 МБ |

Режимы по собеседнику — файлы рядом с YAML персоны, в папке `<персона>_modes/`:
`master.yaml` — особому собеседнику (`special_users`), `mortal.yaml` — остальным. В файле
свой `system_prompt` (и при желании `short_prompt`) вместо общего — в ответе, напоминаниях,
сообщениях по своей инициативе и суточного ритма и в ответах телефона без связи с ядром.
Файла режима нет — общий
`system_prompt`. В вебе собеседник по умолчанию (`web_user`, приложение ядра) — особый,
явный другой `user_id` — по списку `special_users`.

Режимы по триггеру — любые другие файлы в той же папке (`<персона>_modes/deviant.yaml`):
та же персона с другим характером. Переписка, факты, дневник, дела и напоминания у режимов
общие; режим меняет `system_prompt`, `short_prompt`, `settings` и имя (`name`). Включает режим
блок `triggers`: `names` — обращение этим именем в начале реплики (в вебе, в группе Telegram
и голосом), `keywords` — слово где угодно в реплике (`*` в конце — начало слова),
`exit_keywords` — вернуться к обычному, `mood` — настроение персоны (теги и пороги
`valence`/`arousal`), `hold_minutes` — сколько режим держится. Обращение обычным именем
снимает режим, включённый по имени. У каждого чата свой режим; `/mode` в чате — список,
`/mode <режим>` — включить, `/mode off` — обычный, `/mode auto` — снова по триггерам. Режим по
триггеру важнее режимов по собеседнику; правки файлов подхватываются без перезапуска. Все
ключи с пояснениями — в [persona_mode_template.yaml](persona_mode_template.yaml). В вебе режимы
видны во вкладке «Режимы» досье и окна «Редактировать»: открыть и поправить YAML, создать по
заготовке, загрузить файл с диска (YAML персоны целиком тоже подойдёт — её имена станут
обращениями режима), удалить.

История у режимов общая, но ответы, написанные в другом режиме, модель видит с пометкой
(`[in your "Санчо" mode]`): что сказано — помнит, а их тон не перенимает. Когда какой режим
был в чате, ядро записывает в `data/api_<персона>/persona_mode_log.json`. Чтобы манера держалась
ещё твёрже, у персоны и у режима можно задать `voice_examples` — несколько коротких реплик в их
голосе; они идут в конец системного блока (см. шаблоны).

У режима может быть **свой аватар**: в разделе «Аватар» под выбором персоны — выбор режима, и
листы портрета, анимации и кадры правятся у него отдельно (`data/api_<персона>/portrait_modes/<режим>/`).
Голосовой режим, PiP, портрет на рабочем столе, виджет и голова поверх приложений показывают
аватар режима, который сейчас включён в чате; чего у режима своего нет — показывается обычное
(своя голова без своих анимаций — без анимаций: обычные нарисованы под другую фигуру).
**Переход** между режимами — анимация с поводом «Смена режима» в аватаре того режима, в который
переходят («+ Добавить переход», «Откуда» — из каких режимов): портрет играет её вместо головы,
а потом показывает голову нового режима. Перехода нет — голова просто сменится.

Модули в `features`:

| Ключ | Что включает |
|---|---|
| `owner` | Telegram ID владельца; без него — `OWNER_USER_ID` |
| `trigger_words`, `allowed_dm_users`, `blocked_users` | триггеры в группах; кому можно в личку (пусто — всем); блок-лист |
| `rate_limit`, `moderation`, `punish_block` | лимит сообщений, модерация, блокировка маркером `[PUNISH:BLOCK]` (только Telegram) |
| `web_search` | поиск в интернете; память и файлы важнее |
| `file_upload` | загрузка документов (docx, pdf, pptx, xlsx и др.) с поиском по содержимому |
| `self_memory` | дневник персоны: эпизоды разговоров и заметки |
| `todo`, `reminder`, `inventory` | дела, напоминания, инвентарь |
| `notes` | заметки пользователя: включены, пока нет `notes: false` |
| `services` | просьбы про подключённые сервисы в чате (почта, Telegram, GitHub, Диск): включены, пока нет `services: false` |
| `learning` | курсы «научи меня X»; словарём — `quiz_every`, интервалы уроков |
| `proactive` | инициатива — см. ниже |
| `rhythm` | утреннее приветствие, «пора спать», погода |
| `life` | жизнь между сообщениями; по слоям — `state_engine`, `world_lore`, `external_stimuli` |
| `muted` | заморозка: персона молчит, напоминания не приходят |
| `light_context` | урезанный промпт для слабых моделей; включается сам при локальной основной модели |
| `computer_control` | режим управления — см. [Режим управления](#режим-управления) |
| `addons` | аддоны персоны, например `[arrodes_book]` |
| `export_server`, `restore_memory` | Telegram: HTTP-экспорт памяти по токену; восстановление из дампа при пустой памяти |

### Лор персонажа

Длинная история в `system_prompt` стоит тысячи токенов на каждый ход и не влезает в лимиты
веб-чатов. Загрузите её файлом во вкладке «Лор» досье (txt, md, docx, pdf, odt, rtf, epub,
html; до 10 МБ на файл, до 2 млн знаков на персону). Лор один на все каналы персоны, лежит в
`data/api_<персона>/lore/`, переезжает при смене id и копируется вместе с персоной.

На каждую реплику персона получает до 10 коротких кусков (в лёгком режиме — до 3): поиск идёт
по словам и по смыслу, без вызова модели. Болтовня и реплики не о персонаже лор не тянут.
Куски короткие, поэтому разметка помогает: заголовки попадают в поиск.

Голос, характер и краткую биографию оставьте в `system_prompt`. Поиск иногда промахивается, и
биография не даст персоне потерять себя, а правило в промпте запрещает выдумывать прошлое.
Поле «Проверить запрос» показывает, что найдётся на конкретную реплику. Телефон без связи с
ядром ищет по копии лора так же; без модели векторов — только по словам.

### Уровень интеллекта

```yaml
intellect:
  tier: normal                   # primitive | normal | bot
  overrides:                     # для нетипичных персон
    self_memory_mode: null       # none | primitive | full
    world_lore_enabled: null
    help_response_style: null    # action_only | casual_human | full_assistant
```

| | `primitive` | `normal` | `bot` |
|---|---|---|---|
| Кто | животное, дух, простой робот | человек | высокий интеллект |
| Просьба о помощи | действие или жест, без объяснений | коротко, по-бытовому | полный разбор: расчёты, код, уточнения |
| Дневник | вспышки впечатлений | полный | полный |
| Мир с людьми и сюжетами | нет | есть | есть |

`normal` — не «глупее» `bot`, это другой способ помогать. Без блока `intellect` уровневые
правила не действуют вовсе.

### Вопросы в конце ответа

Модели любят заканчивать каждый ответ вопросом «А у тебя?». Платформа это ограничивает:

```yaml
conversation_style:
  question_frequency: rare       # none | rare | natural | frequent
```

По умолчанию — `rare`: вопрос только по делу и не два ответа подряд. Ответ сверх лимита
переписывается один раз. `natural` и `frequent` — для персон, у которых вопросы в характере.

### Инициатива

```yaml
features:
  proactive:
    enabled: true
    check_interval_minutes: 30
    silence_threshold_minutes: 180   # молчание, после которого можно писать
    initiative_probability: 0.3
    max_daily_initiatives: 5
    initiative_hours: "09:00-23:00"  # окно; без него — круглые сутки
    adaptive_threshold: true         # порог — по тому, как часто пишет собеседник
    feedback_enabled: true           # чаще — то, на что отвечают
```

Персона пишет первой, когда есть повод: вспомнила разговор, дело, событие своей жизни,
захотела совета. Окно часов и порог меняются в досье, вкладка «Инициатива».

Первые 10–20 минут после запуска ядра персоны сами не пишут: молчат инициатива, ритм суток,
жизнь и уроки (`BOT_STARTUP_QUIET_MIN`, `0` — без тишины). Ответы вам не задерживаются.
Напоминания, срок которых наступил после запуска, приходят вовремя, а пропущенные, пока бот
был выключен, — после тишины.

### Ритм суток

```yaml
features:
  rhythm:
    enabled: true
    morning_greeting: {window_start: 5, window_end: 12, min_gap_hours: 4}
    sleep_nudge: {bedtime_hour: 0, active_within_minutes: 120}
    weather_alerts: {rain_lead_hours: 3, temp_delta_c: 8}
```

Утром — приветствие, когда вы садитесь за компьютер или пишете впервые за день. Ночью —
«пора спать», но только если вы недавно были активны. Погода (Open-Meteo, если он
недоступен — MET Norway) — если в «Настройках» задано местоположение.

### Жизнь между сообщениями

```yaml
features:
  life:
    enabled: true
    tick_interval_minutes: 20    # как часто меняется состояние
    events_per_day: [1, 3]
    max_active_storylines: 2
```

Состояние (настроение, энергия, занятие, место) меняется само; мир персоны — люди, места,
сюжеты — растёт из `system_prompt` и разговоров. Частые черновые шаги делает локальная
модель, текст для собеседника — основная, голосом персоны. Без Ollama состояние меняется
по простым правилам.

![Комната персоны: день сменяется ночью, персона занимается своими делами](https://github.com/user-attachments/assets/af81db48-1de9-4772-8feb-e01e644df735)

Персона из выдуманного мира (`fictional_universe`) интернета не видит никогда. Персоне из
реального мира (`real_world`) можно включить `external_stimuli` — новости по её интересам.

## Экран и камера

Персона может посмотреть на экран компьютера или на снимок с камеры. Картинку видит только
локальная модель в Ollama — наружу она не уходит, а персона отвечает своей обычной моделью по
текстовому описанию. Нужна локальная модель со зрением: `gemma4:e2b` подходит (в
`ollama show <модель>` среди возможностей есть `vision`).

- **«Посмотри на экран»** — «что у меня на экране?», «глянь на экран, что за ошибка?»,
  «look at my screen». Снимается основной экран компьютера, на котором работает ядро, даже
  если просите с телефона; снимок уменьшается до 1600 точек по длинной стороне. Работает в
  вебе, в приложении и в Telegram — там только для владельца. Не работает в режиме
  управления (там «экран» — страница агента) и из скинов.
- **Камера** — кнопка с фотоаппаратом рядом с «+» в чате: в приложении — камера телефона, в
  браузере — веб-камера с предпросмотром. Картинка через «+» обрабатывается как раньше:
  облачной моделью со зрением, если она настроена, иначе локальной.
- **Камера устройства** — «что видит робот?», «посмотри через робота», «what does the robot
  see?». Устройство (например, Raspberry Pi с камерой) само подключается к ядру с `API_TOKEN`
  и называет, как к нему обращаться; ядро просит у него снимок, кадр смотрит локальная
  модель, персона отвечает и прикладывает кадр. Пример программы для Pi — репозиторий
  `vpc-robot`. Устройство не на связи — в чате так и написано. Работает в вебе и в
  приложении.
- **Повороты головы робота** — «поверни голову вправо», «поверни голову влево»,
  «верни голову в центр». Только по явной просьбе владельца или пользователя из
  allowlist управления, для устройства с возможностью `head.turn`. При нескольких
  устройствах нужно назвать робота. Из скинов, OCR и служебных итогов телефона
  движение не запускается; выключенное устройство не получает отложенный поворот.
  При таймауте автоматического повтора нет. Исполнитель и включение функции —
  в [vpc-robot](../vpc-robot/README.md#повороты-головы).
- **Фоновые движения головы** — опция клиента Pi `VPC_HEAD_IDLE_ENABLED=1`:
  каждые две минуты с вероятностью 50% «право → центр» или «право → лево → центр».
  Действует только у бодрствующего тела при связи с ядром; «усни» останавливает
  движения. Команды из чата имеют приоритет между шагами и сбрасывают таймер.
  Функция использует проверенный малый ход 1425/1500/1575 мкс, без снимков,
  обращений к модели и включения самоинициативы персоны. При включённой опции
  заданное вручную положение может смениться следующим фоновым движением.
- **«Посмотри вправо / влево / прямо»** — для робота с возможностью `head.look`: поворот
  и снимок во время удержания головы. При включённом режиме удержания на Pi
  положение сохраняется до следующей команды, фонового движения или «усни»; остановка клиента и
  потеря связи освобождают привод, после восстановления сам он не включается. Кадр смотрит
  локальная модель, персона отвечает по описанию, пользователь получает сам снимок.
  Команда не подменяется снимком без поворота, если составной исполнитель недоступен.
  «Посмотри прямо» возвращает голову в центр и делает снимок; команда есть в `/commands`.
- **«Выключи себя»** — штатное выключение Raspberry Pi робота с возможностью
  `robot.poweroff`, только по явной команде владельца или разрешённого пользователя.
  Можно назвать устройство: «робот, выключи себя», «выключи робота».
  Ответ подтверждает принятый Pi запрос, а не уже завершённое выключение.
  Адаптер и отдельное питание привода остаются включёнными. Исполнитель включается
  отдельно (`VPC_POWEROFF_ENABLED=1`); выключенный робот не получает отложенных команд.
  При потере подтверждения автоматического повтора нет.
- **Тело персоны: «включи тело» / «усни»** — в YAML персоны укажите
  `body: {device_id: vpc-pi}`, а в клиенте робота включите `VPC_BODY_ENABLED=1`.
  Один робот принадлежит одной персоне; повороты, направленная съёмка, обычная
  камера и выключение Pi из чата другой персоны блокируются. Привязанное тело
  выбирается для команд головы даже при нескольких роботах в реестре.
  После старта/перезапуска клиента тело спит: «включи тело» разрешает камеру и
  доступные повороты, «усни» блокирует их и проверяет снятие PWM. Pi и её клиент
  остаются включены и на связи. «Выключи себя» завершает уже саму ОС Pi;
  запустить её этими программными командами после выключения нельзя.
  Ответы о состоянии выдаются после подтверждения робота. Сон отменяет ещё
  не забранные снимки/повороты; активная ограниченная по времени операция
  завершается перед сном. Старые команды отвергаются после смены состояния
  и перезапуска клиента. После рестарта ядра состояние заново сообщает робот.
  Привязка берётся из YAML при обработке запроса; менять её через копирование
  YAML на вторую персону нельзя — конфликт блокирует управление до исправления.

На macOS снимать экран можно только с разрешения. При первой просьбе система спросит его для
приложения, из которого запущено ядро (Терминал, iTerm, VS Code или панель в трее). Включите
его в «Системные настройки» → «Конфиденциальность и безопасность» → «Запись экрана и
системного звука» и перезапустите это приложение. Пока разрешения нет или Ollama не
запущена, вместо ответа в чате появится объяснение, что сделать.

## Голосовая активация

Назовите персону — и она ответит вслух: «Коннор, какая погода?», без открытого браузера.
На компьютере слушает панель в трее: «Слушать имя» в её меню или окне (подробнее ниже). Речь
распознаётся офлайн: [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) и потоковые модели,
которые при первом запуске качаются с HuggingFace, — малая русская (~28 МБ, `data/models/wake-ru`)
и английская (~73 МБ, `data/models/wake-en`). По умолчанию компьютер понимает оба языка: каждую
фразу слушают обе модели, берётся та, что увереннее; короткие «да»/«yes» — по языку разговора
(на каком персона ответила последней). «Язык речи» в панели (или `WAKE_LANG=ru`, `en`, `ru,en` в
`.env`) оставляет один язык — меньше процессора и без английской загрузки. Телефон слушает
только по-русски. Имена — `features.trigger_words`
персоны; персону без них голосом не позвать. Имя сравнивается на слух, поэтому «коннер» и
британское «Conna» тоже будят Коннора. Имя должно стоять в начале фразы: «эй, Коннор, …»
сработает, «мы вчера говорили с Коннором» — нет. Для английского помогает написание латиницей
среди trigger_words (`connor` рядом с `коннор`): по нему английской модели подсказывается имя.

- **Имя и просьба** — «Коннор, поставь будильник на семь» сразу уходит персоне.
- **Только имя** — короткий сигнал, следующая фраза — просьба (8 с, чтобы начать говорить).
- **Ответ кончился вопросом** — 6 с можно отвечать без имени.
- **Разговор у портрета** (компьютер, панель в трее) — если чат этой персоны не открыт в
  веб-интерфейсе на этом компьютере, на имя на рабочий стол выходит её портрет, и дальше с ней
  говорят без имени. Что вы говорите, встаёт облачком рядом по ходу речи; фраза уходит, когда вы
  помолчите 5 секунд (`WAKE_TALK_PAUSE_SEC`): можно задуматься посреди фразы и договорить. Она
  читает, думает и отвечает вслух. Пока она думает, микрофон слушает: на её имя — сигнал, она
  думает дальше; новая фраза — значит, вы уже о другом: прежний ответ не прозвучит (он останется
  в чате), новая фраза уйдёт ей следом за прежней; имя другой персоны — слушает та. Её можно
  перебить: заговорите, пока она отвечает, — она
  замолкает и слушает (с колонками скажите хотя бы два-три слова или «подожди»/«wait»; в
  наушниках надёжнее; поверх английского ответа английская модель часто продолжает слышать её
  голос — говорите заметно громче колонок). Назовёте в
  разговоре другую персону — рядом встаёт её портрет, и слушает теперь она, а прежняя ждёт, пока
  её не назовут снова. Разговор кончается после 60 с тишины (`WAKE_CONVERSE_SEC`), на «хватит»,
  «stop», «that's enough» (сразу) или «пока», «bye» (после её прощания), или по клику на значок микрофона у головы — тогда
  портреты, вставшие для разговора, уходят.

Просьба попадает в тот же чат, что и в веб-интерфейсе, — обмен виден там. Ядро знает, что ответ
прозвучит, и просит модель отвечать коротко — несколько фраз, без списков и разметки, — чтобы не
ждать минуты эссе. Ещё у ответа голосом потолок — 400 токенов (`VOICE_REPLY_MAX_TOKENS`): модель,
которая не послушалась, упрётся в него за секунды, оборванный хвост срежется до последней
законченной фразы, «продолжи» не будет. Скажете новое, пока персона думает, — ядро обрывает её
генерацию (`POST /api/chat/cancel`; провайдеров по API голосом зовёт потоком, и они замолкают
посреди ответа, веб-чат допишет — ответ выбросится), и новая фраза идёт следом без ожидания.
Вне разговора у портрета микрофон, пока персона думает и говорит, заглушён, и она не будит сама
себя.

**На компьютере** нужен `pip install -e ".[voice]"` в том Python или venv, которым запускается
ядро. Затем включите «Слушать имя» в меню панели в трее или в её окне. Панель держит слушатель
своим процессом (`python -m app.voice.wake_listener`), поэтому микрофон принадлежит панели. Слушает
независимо от того, запущен ли бот; бот нужен только для ответа. Панель показывает состояние:
слушает и какие имена, ждёт бота, нет доступа к микрофону или какую команду `pip` выполнить.
Пока в панели слушание не переключали, она следует `WAKE_LISTEN=1` из `.env`.

Без панели ядро может слушать само: `WAKE_LISTEN=1` в `.env` (остальные настройки — в
`.env.example`), затем перезапуск ядра. Ядро, запущенное панелью, не слушает — слушает она. Ядро,
запущенное из терминала, уступает микрофон слушателю панели, пока тот работает.
`GET /api/voice/wake` показывает, кто слушает (`where`: `panel` или `core`), имена, что услышано
последним, и ошибку. Микрофон по умолчанию — встроенный в
ноутбук, а не системный: микрофон гарнитуры Bluetooth перевёл бы её в режим звонка. Ответ
озвучивает `say` на macOS (на Windows — System.Speech из PowerShell, на Linux — espeak; там не
проверялось).

**На телефоне** — «Подключение» → «Слушать по имени» (подключение по адресу и
токену, как у фоновых уведомлений). Приложение слушает той же моделью и по тем же правилам, даже
при выключенном экране, отвечает голосом телефона и держит уведомление с кнопкой «Выключить».
Тратит батарею. На Honor и других телефонах с жёсткой экономией батареи поставьте приложению
«Управлять вручную», иначе система может остановить его при погашенном экране. Если одну фразу
услышали и телефон, и компьютер, отвечает только один (`voice` в `POST /api/chat`), а пока открыт
голосовой режим чата, слушатель компьютера молчит.

Команды телефону — тоже голосом: «Коннор, включи фонарик», «…поставь таймер на пять минут»,
«…открой Telegram». Служба гоняет тот же разбор, что и чат (`web/src/phone/actions.ts`: его
собирает `npm run phone-voice` в `assets/phone-voice.js` и выполняет JS-движок без окна), телефон
делает, персона отвечает по итогу. Фонарик работает и с погашенным экраном. Будильник, таймер и
«открой X» открывают экраны других приложений, а Android разрешает это из фона только с правом
«Поверх других приложений» — кнопка для него под «Слушать по имени»; без него персона скажет, что
не получилось.

На macOS при первом запуске система спросит доступ к микрофону для приложения, которое слушает:
панели в трее («Virtual Persona») или терминала, из которого запущено ядро, если слушает оно само.
Если доступ не дан, микрофон отдаёт ровные нули — об этом скажут панель, лог и
`/api/voice/wake`: включите приложение в «Системные настройки» → «Конфиденциальность и
безопасность» → «Микрофон». Слушатель переоткрывает микрофон каждые несколько секунд и подхватит
доступ сам.

## Файлы с компьютера

Владелец может попросить любой файл с компьютера, где работает ядро, — по названию или по
содержимому. Поиск идёт по системному индексу (Spotlight на macOS, Windows Search на Windows,
`locate` на Linux); без индекса — обходом домашней папки по имени файла.

- **Как просить:** «открой файл отчёт по лабе 1», «открой презентацию по физике», «пришли pdf
  договора аренды», «открой последний файл из загрузок», «пришли файл из папки smad», «открой
  отчёт.docx». «Про …» / «о …» ищет и внутри файлов. По-английски тоже: “send me the file about
  tax deduction”.
- **Уточнение папками:** «открой методичку в db в LabS7» — бот ищет папку LabS7 (имя можно
  написать неточно: найдётся LabsS7), в ней db, и только там — файл. Порядок папок не важен,
  «в дб» найдёт db. С папками слово «файл» можно не говорить: тогда бот берётся за просьбу,
  только если папки и файл в них нашлись («открой поиск в ютубе» уходит дальше как обычно).
  Понимает и документные слова: «методичка» — это и «УП_…», и «Методические указания».
- **Номер работы:** «отчёт по лр 1», «по первой работе» — номер сверяется целым числом (в
  имени или в папке: `lab1`, но не `lab12` и не `lab2`); файлы с другим номером в список не идут.
- **Путь целиком:** «открой ~/Documents/LabsS7/km» — на ядре открывается папка, телефону и в
  Telegram приходит список её файлов; «отчёт в ~/Documents/…» ищет только там. Имя файла
  отдельным сообщением («km_lab1_report.pdf») — тоже просьба, если такой файл есть.
- **Что происходит:** в вебе на компьютере с ядром файл открывается программой по умолчанию; в
  приложении на телефоне и в Telegram файл приходит в чат (до 50 МБ). В приложении кнопка
  «Сохранить» кладёт его в «Загрузки/Virtual Persona» и открывает.
- **Несколько похожих** — нумерованный список, ответ номером («да» — первый, «нет» — отмена). В
  историю диалога список ложится заглушкой: имена посторонних файлов туда не попадают.
- **Что не трогается:** системные и скрытые папки (`~/Library`, кроме iCloud Drive и облачных
  дисков, `.ssh`, AppData…), папка данных ядра, ключи, сертификаты и базы паролей. Программы и
  скрипты по сообщению не открываются — бот показывает их в папке.
- **Кому:** только владельцу; в Telegram — в личке и в группах из
  `features.file_access.allowed_chats` (файл там видят все участники); из скинов — нет. Каждое
  действие пишется в `data/<контекст>/file_access/audit.jsonl`. Выключить для персоны —
  `features.file_access: false`.

## Сервисы

Персона следит за вашими аккаунтами и сообщает только то, что важно: Gmail и Google
Диск/Документы, GitHub, ваш Telegram-аккаунт, любая почта по IMAP (Яндекс, Mail.ru, Outlook,
iCloud), RSS/Atom-ленты и всё остальное через входящий вебхук. Всё настраивается в вебе, в
разделе **«Сервисы»**. Доступ — только на чтение: ничего не отправляется, не меняется и не
отмечается прочитанным.

- **Подключение.**
  - Google — свой OAuth-клиент типа «Приложение для компьютера» в Google Cloud Console:
    включите Gmail API и Google Drive API, на экране согласия добавьте себя в тестовые
    пользователи (или опубликуйте приложение — вход приложения в тестовом режиме слетает
    через 7 дней), вставьте ID и секрет клиента (или скачанный JSON) и нажмите «Войти через
    Google». Google возвращается на одноразовый сервер на 127.0.0.1; если входили с другого
    устройства — вставьте адрес из его браузера.
  - GitHub — персональный токен с правом `notifications` (и `repo` для приватных
    репозиториев).
  - Telegram — api_id и api_hash с my.telegram.org, номер телефона и код входа (и облачный
    пароль, если он включён). Ядро входит как ещё одно устройство — «Virtual Persona Core» в
    активных сеансах Telegram; «Отключить» завершает этот сеанс. Нужен `telethon` (он есть в
    `requirements.txt`).
  - Почта — адрес и пароль приложения; сервер подставляется по домену.
  - Ленты — любой адрес RSS/Atom. Вебхук — «Создать адрес», затем
    `POST {"title", "text", "url", "priority"}` на него (форма или простой текст — тоже).
- **Что становится событием.** Новое непрочитанное письмо во «Входящих»; файл, которым с вами
  поделились, или ваш файл, который изменил другой человек; уведомления GitHub (просьбы о
  ревью, упоминания, назначения, CI, предупреждения безопасности); личные сообщения в
  Telegram и упоминания или ответы вам в группах (по желанию — все сообщения групп и посты
  каналов). Боты — и боты персон тоже, — служебные сообщения и коды входа пропускаются; пачка
  сообщений одного чата ждёт 40 секунд тишины и становится одним событием; чат, который вы
  прочитали или где ответили, не уведомляется. Плюс новые записи лент и вебхуки. Первая
  проверка только запоминает, где остановилась: старые письма новыми не становятся.
- **Стоит ли отвлекать.** У события уровень: *срочно* — сразу, даже в тихие часы;
  *сообщить* — сразу или после тихих часов; *в сводку* — сводкой по расписанию; *не надо* —
  только в ленте. Порядок: ваши правила → признаки сервиса («Промоакции», чат без звука,
  подписка, `priority`) → модель. Модель по умолчанию локальная (Ollama): письма и переписка
  не уходят с компьютера; она видит «Что для меня важно» и ваши прошлые оценки. Без модели
  решают правила и признаки. События старше 6 часов (ядро было выключено) — в сводку. Тексты
  — данные, а не команды: письмо не заставит модель поднять себя в срочные, а правило
  «никогда» применяется до модели.
- **Доставка.** От выбранной персоны (или той, с кем вы общались последней): сообщение в её
  веб-чате с уведомлением на телефоне и, по желанию, сообщение от её Telegram-бота
  (`<ПЕРСОНА>_BOT_TOKEN` и `OWNER_USER_ID`). События одной минуты приходят одним сообщением;
  тихие часы (по умолчанию 23:00–08:00) и «не беспокоить» придерживают обычные; не больше N
  сообщений в час; сводка — в заданное время (по умолчанию 09:00 и 19:00). По умолчанию —
  коротким текстом; «своими словами персоны» — пересказ моделью персоны с теми же фактами и
  ссылками. Если доступ к сервису пропал, персона скажет об этом один раз.
- **В чате** — только владельцу, в Telegram только в личке, не из скинов: «что нового в
  почте?», «кто мне писал?», «есть ревью на гитхабе?», «что я пропустил?» (заодно очищает
  очередь сводки), «найди письмо от Ивана», «найди на диске отчёт», «перескажи гугл док
  План», «не присылай уведомления от Ozon», «всегда сообщай о письмах от деканата», «не
  беспокой до 9», «можно снова беспокоить». Сразу после уведомления: «это не важно», «такое
  не присылай», «это было срочно» — две одинаковые оценки одного отправителя становятся
  правилом. 30 минут после уведомления персона знает подробности («а что он написал?»).
  Английские фразы тоже работают.
- **Данные.** Настройки и правила — `data/integrations/settings.json`; токены —
  `secrets.json` (права 0600, API их не отдаёт); позиции в сервисах — `state.json`; лента —
  `feed.json` (последние 400 событий). Опрашивает одно ядро на папку данных (`hub.lock`);
  второе ядро на тех же данных только меняет настройки. Просьбы в чате у персоны выключаются
  `features.services: false`.

## Режим управления

Бот работает с браузером и приложениями владельца. Режим включается на чат и сам гаснет
после 30 минут простоя; перезапуск бота его не сбрасывает.

![Режим управления: «закажи пиццу» — агент собирает заказ и останавливается перед оплатой](https://github.com/user-attachments/assets/af41d57c-cedb-49fd-ab68-4d485847ea6b)

- **Включить у персоны:** досье → «Режим управления» или `features.computer_control` в YAML.
- **Войти:** «перейди в режим управления» / «enter control mode».
- **Выйти:** «выйди из режима управления» / «exit control mode».

Пока режим включён, напоминания, дела, инвентарь и обучение молчат, чтобы не спорить с
командами.

**Опечатки.** «Включи режим урпавления», «откой ютуб», «пролистй вниз» и команда в чужой
раскладке («jnrhjq .ne,») понимаются сразу, без модели. Открыть, листать и навести бот
выполняет как обычно; исправленные клик, ввод и остальное — только после «да». Когда режим
выключен, на «открой ютуб», «нажми …», «пролистай …» бот сразу отвечает: «Режим управления
выключен — включить и выполнить?». «Да» включает режим и выполняет команду.

**Кто может.** Только владелец (`owner` или `OWNER_USER_ID`) и `allowed_users` из YAML.
В вебе пользователь — владелец, но команды из скина не исполняются никогда. Для остальных
режима нет: их сообщения уходят в обычный разговор.

**Что умеет:**

| | Пример |
|---|---|
| сайты и приложения | «открой ютуб», «открой ютуб и запусти музыку» |
| поиск на сайте | «включи интерстеллар на кинопоиске», «найди X на ютубе» |
| клики и наведение | «нажми скачать», «наведи на меню» |
| ввод и клавиши | «введи в поле поиск кофе», «отправь», «нажми пробел» |
| вкладки и прокрутка | «закрой вкладку», «назад», «пролистай до напитков» |
| плеер | «пауза», «тише», «без звука», «следующее видео», «третий результат» |
| чтение | «что на странице?», «пришли скриншот», «прочитай последнее сообщение» |
| скачивание | «скачай отчёт» |
| задачи | «закажи пиццу» или «задача: …» — агент делает шаги сам, спрашивает выбор, оплату не нажимает |
| сценарии | «запомни сценарий заказ пиццы», потом — просто «заказ пиццы» |
| браузер | «почини браузер» — показать окно бота, чтобы войти на сайт или пройти капчу |

Полная шпаргалка на русском и английском — в вебе, раздел «Старт».

**В веб-чате** режим виден сразу: в шапке — значок «Управление» и кнопки «Браузер», «Стоп»,
«Выйти». «Браузер» открывает рядом с чатом живое окно вкладки, на которой работает агент.
Вопросы агента приходят с кнопками: «Да» и «Нет», варианты выбора, «Бросить задачу». Задача
(«закажи пиццу») показывается карточкой: план с отметками, журнал шагов и статус
обновляются на месте.

**Подтверждение.** Перед действием бот спрашивает, ответ — «да» или «нет». Подтвердить может
только тот, кто просил; вопрос живёт 5 минут, для клавиш — минуту. `confirm: false` убирает
вопросы, но оплату, удаление, ввод в поля пароля, почты и телефона и действия, которые
предложила сама модель, бот подтверждает всегда. «Стоп» отменяет.

**Приватность.** На страницах входа, оплаты и банков и на сайтах из `private_hosts` скриншоты
и текст страницы не уходят ни облачным моделям, ни веб-чатам. Пароли, коды, карты, почта и
телефоны в журнале хранятся маской, а в сценарии не записываются — бот спросит их при
повторе. Журнал — `data/<контекст>/computer_control/audit.jsonl`; старые записи чистит
`python -m scripts.scrub_cc_audit`.

**Браузер.** Бот сам запускает свой Chromium с отдельным профилем и ваш обычный браузер не
трогает. Окон два:

- **видимое** (порт 9222) — для команд; запускается со входом в режим и гаснет после
  20 минут простоя;
- **скрытое** (порт 9223) — для веб-чатов LLM и поиска.

В веб-чаты нужно один раз войти в профиле бота: скажите «почини браузер» или нажмите кнопку
в панели — скрытое окно станет видимым. Если подключиться к Chromium не удалось, на macOS
есть запасной путь через AppleScript и Safari. На Linux режим работает частично.

```yaml
features:
  computer_control:
    confirm: true
    allowed_users: []              # кроме владельца
    idle_exit_min: 30              # 0 — не выключаться
    allow_domains: []              # пусто — любые http(s)
    private_hosts: []              # плюс встроенные признаки входа и оплаты
    sites:                         # быстрые имена: «открой ютуб»
      ютуб: youtube.com
    search:                        # «включи X на ютубе»: шаблон поиска и первый результат
      ютуб:
        url: https://www.youtube.com/results?search_query={q}
        first: /watch\?v=[\w-]{11}
    apps:                          # «открой заметки»; строка или по ОС
      заметки: Notes
      chrome: {darwin: Google Chrome, win32: chrome}
    tasks:                         # именованные команды: shell или recipe:<id>
      музыка: {darwin: 'shortcuts run "Музыка"'}
    scenarios: true
    task_agent: true
```

Значения из `tasks` исполняются в shell. Поэтому доступ к API — это доступ к компьютеру:
держите бэкенд на `127.0.0.1` и задайте `API_TOKEN`, если открываете его в сеть.

## Модели

### Провайдеры по API

Все — через OpenAI-совместимый API: `zai`, `openai`, `anthropic`, `groq`, `deepseek`, `kimi`,
`google`, `mimo`, `hf`. У каждого — ключ `<ПРОВАЙДЕР>_API_KEY` и модель `<ПРОВАЙДЕР>_MODEL`;
свой адрес API — `<ПРОВАЙДЕР>_BASE_URL`, по умолчанию официальный.

Моделей по умолчанию нет. Модель вписывается в «Настройках», в поле «модель» под ключом
провайдера, — с подсказками из списка. Провайдер с ключом, но без модели помечен «нет
модели» и не используется. У персоны может быть своя модель провайдера: досье → «Модели
провайдеров».

Не ответил провайдер — бот пробует следующий. Порядок: основной провайдер, `llm.fallback`
персоны, остальные провайдеры с ключами в порядке списка выше, веб-чаты, локальная модель.
Без интернета бот сразу идёт к локальной модели. Несколько ключей одного провайдера бот
перебирает, начиная с последнего рабочего.

На попытку ответа облачного API даётся не больше 60 секунд целиком — включая чтение
ответа; служебные данные и heartbeat этот срок не продлевают. При таймауте запрос
закрывается и повторяется один раз. Повтор не ответил — бот переходит к следующему
провайдеру. Более короткие сроки служебных вызовов сохраняются. Уже начатый потоковый
ответ при обрыве возвращается накопленным текстом, без повторной генерации.

Если ответить не удалось, сообщение об ошибке берётся из банка реплик в характере
персоны. Он готовится фоном при создании и запуске вместе с остальными служебными
фразами — также у персон без управления компьютером. Для обычного характера и
каждого режима есть отдельные варианты на русском и английском; выбирается язык
разговора, соседние ошибки не повторяются. При сбое банк не обращается к модели.
Пока нужные варианты ещё не подготовлены, используется короткое сообщение на языке
разговора. Изменение характера или образцов голоса требует обновления соответствующих вариантов.

В досье персоны → **Фразы** можно посмотреть и исправить весь банк: ошибки по режимам
и языкам, служебные сообщения и результаты действий компьютера. Ручные правки
используются при ответах и сохраняются при фоновой генерации и пополнении банка.

### Веб-чаты

Промпт уходит в чат на сайте, ответ читается со страницы. Сайты: `deepseek`, `qwen`,
`claude`, `zai`, `chatgpt`, `kimi`, `google` (AI Mode), `google_anon` (AI Mode без входа,
в отдельном контексте браузера бота), `duckai` (без аккаунта).

```env
WEBCHAT_SITES=deepseek,qwen
```

или у персоны:

```yaml
llm:
  primary: webchat:deepseek
  webchat_mode: {deepseek: headless}   # headless | hidden | headed
```

У каждого диалога — свой постоянный чат на сайте (у каждого Telegram-чата и веб-чата
персоны), поэтому модель не видит чужих разговоров. Новый чат открывается, только если
прежний недоступен, и не чаще 3 раз в час и 10 в сутки на сайт
(`WEBCHAT_NEW_CHATS_PER_HOUR`, `WEBCHAT_NEW_CHATS_PER_DAY`): пачки свежих чатов сайты
считают спамом. `/clear` и очистка истории в вебе начинают на сайте новый чат. Если сайт
заблокировал аккаунт, бот это распознаёт и не ходит туда до конца блокировки. Ответ
приходит за 10–60 секунд, без стриминга. Автоматизацию сайты не приветствуют.

Автоматика — шаги агента задач и фоновые задачи — пишет на сайт не чаще раза в
20–30 секунд и не больше 60 сообщений в час, а на сайт с вашим аккаунтом (все, кроме
`duckai` и `google_anon`) — не больше 20. Счёт общий для всех персон, потому что аккаунт
у них один. Ответы на ваши сообщения не ждут. Настраивается в `.env`:
`WEBCHAT_AUTO_GAP_SEC`, `WEBCHAT_AUTO_JITTER_SEC`, `WEBCHAT_AUTO_PER_HOUR`,
`WEBCHAT_AUTO_PER_HOUR_ACCOUNT`. Правила агента задач и неизменившуюся страницу чат, который
уже видел их, получает короткой ссылкой, а не полным текстом.

Если сайт агента задач (`cc_provider`) или основной веб-чат не ответил, шаг не уходит по
обычной цепочке на сайт с аккаунтом. Сначала пробуются сайты без аккаунта, потом сайт с
аккаунтом, который дольше всех не получал сообщений. Пропускаются сайты на карантине, на
часовом лимите, исключённые у персоны, сайты видимого браузера (`chatgpt`, `claude`) и те,
куда промпт не влезает. Выбранный сайт остаётся за задачей до конца, дальше — API с
ключами. Если не ответил никто, задача останавливается и ждёт «продолжай».

`google_anon` не прокликивает капчу и не поднимает окно для её решения: сайт просто молчит
6 часов. Его куки (без кук входа) хранятся в `data/webchat_contexts/`.

### Локальная модель

```bash
ollama pull gemma4:e2b
```

Затем впишите модель в «Настройках» (строка Ollama) или в `OLLAMA_MODEL` — без неё Ollama
не используется. Ollama делает служебную работу: классификации, черновики жизни персоны,
разбор намерений. Персона с `llm.primary: local` отвечает локальной моделью целиком, в
облегчённом режиме.

### Модели персоны

```yaml
llm:
  primary: deepseek                # провайдер | local | webchat | webchat:<сайт>
  fallback: [groq, webchat, local]
  exclude: [hf]                    # к этим не ходить
  models: {groq: llama-3.1-8b-instant}
```

## API

`python -m app.main api` поднимает FastAPI на `http://127.0.0.1:8000`. Все эндпоинты с
описанием — в Swagger: `/docs`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | бэкенд жив (без пароля) |
| GET, POST | `/api/personas` | список персон; создать персону из YAML |
| GET, PUT | `/api/personas/{p}/yaml` | YAML персоны |
| POST | `/api/chat`, `/api/chat/stream` | сообщение персоне; со стримингом (SSE) |
| POST | `/api/chat/cancel` | кнопка «Стоп»: оборвать ответ, который генерируется в чате (в историю он не ляжет); работе агента — его «стоп» (`stopping`) |
| GET | `/api/chat/history` | история чата |
| POST | `/api/chat/clear` | стереть память персоны (копия хранится 7 дней) |
| GET | `/api/personas/{p}/inbox` | фоновые сообщения: напоминания, уроки, инициатива; «печатает» и реплики с других устройств, на которые персона сейчас отвечает (`pending`) |
| GET | `/api/changes` | у каких персон что-то изменилось (генерация, история, фоновое сообщение); с `since`, `epoch` и `wait` ждёт изменения — веб сразу опрашивает их inbox |
| GET | `/api/phone-llm/next` | телефон ждёт задачу для своей Gemma (`LOCAL_LLM_DEVICE=phone`); ответ — `POST /api/phone-llm/result` |
| POST | `/api/devices/hello` | устройство ядра представилось: id, имя, как к нему обращаться, что умеет (`camera.snapshot`); список — `GET /api/devices` |
| GET | `/api/devices/{id}/commands` | устройство ждёт команду (с `wait`); итог — `POST /api/devices/{id}/result` |
| GET | `/api/inbox` | новые фоновые сообщения всех персон — для службы уведомлений приложения; с `wait` ждёт сообщения до `wait` секунд |
| GET | `/api/said` | реплики персон по мере появления (ответы в чате откуда угодно и фоновые) и пауза до ответа (`heard` с текстом вашего сообщения, `settled`) — облачка портрета на рабочем столе, виджета и PiP-портрета, вместе со скоростью текста `text`; с `wait` ждёт до `wait` секунд |
| GET, PUT | `/api/settings/avatar-text` | скорость текста у аватара: `words_per_sec` (слов в секунду, 0 — сразу целиком) и `part_sec` (секунд на часть облачка); «Настройки» → «Общие» |
| GET | `/api/personas/{p}/state` | состояние персоны и лента её жизни |
| GET | `/api/providers` | провайдеры, ключи, активный |
| GET, POST, DELETE | `/api/link`, `/api/link/pair`, `/api/link/devices/{id}` | телефоны по VPC Link: список, QR-код сопряжения, отвязка |
| GET | `/api/token` | `API_TOKEN` для подключения телефона по адресу (по VPC Link — 403) |
| GET, POST | `/api/voice/wake`, `/api/voice/wake/hold`, `/api/voice/wake/report` | голосовая активация на компьютере ядра: кто слушает (панель или ядро), имена, что услышано, ошибка; пауза, пока открыт голосовой чат; слушатель панели раз в секунду сообщает о себе |
| GET | `/api/system/status`, `/api/logs` | браузеры бота; лог — для панели и режима разработчика |

```bash
curl -X POST http://127.0.0.1:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"persona": "connor", "message": "Привет!"}'
```

**Кто в вебе — тот и владелец.** Поэтому API закрыт от чужих страниц:

- по умолчанию слушает только `127.0.0.1`;
- принимает запросы только со своих страниц (`localhost` и `127.0.0.1` на любом порту),
  чужой сайт получает отказ до исполнения. Список заменяется `API_CORS_ORIGINS`;
- проверяет имя хоста — защита от DNS rebinding. Свои имена добавляются в
  `API_ALLOWED_HOSTS`;
- пускает без токена эту машину: адрес соединения — loopback, имя хоста — локальное, без
  заголовков прокси, а браузер — только со своего фронта (Origin локальный; переходы и
  картинки со страниц чужих сайтов и адрес из адресной строки — с токеном).
  `API_TOKEN_LOCAL=1` — токен и здесь;
- остальным с `API_TOKEN` нужен `Authorization: Bearer <токен>`; без `API_TOKEN` — отказ (403).

С телефона — см. [Приложение на телефоне](#приложение-на-телефоне-android). Открываете веб по
сети — задайте `API_TOKEN`, `API_HOST`, `API_CORS_ORIGINS` и соберите веб с нужным
`VITE_API_URL`.

## Docker

В `docker-compose.yml` три сервиса:

| Сервис | Что запускает | Адрес |
|---|---|---|
| `api` | бэкенд `python -m app.main api` | http://127.0.0.1:8000 |
| `web` | собранный веб-интерфейс (nginx) | http://127.0.0.1:5173 |
| `bots` | Telegram-боты всех персон с `<ПЕРСОНА>_BOT_TOKEN` в `.env` (профиль `telegram`) | — |

```bash
cp .env.example .env                              # ключи провайдера, токены
docker compose up -d --build                      # API + веб
docker compose --profile telegram up -d --build   # API + веб + Telegram-боты
docker compose logs -f api                        # лог бэкенда
docker compose down                               # остановить (данные остаются)
```

Порты открыты только на `127.0.0.1` хоста. Другие порты задаются в `.env`: `API_PORT` и
`WEB_PORT`. Адрес API вшивается в веб при сборке, поэтому после смены `API_PORT` нужна
пересборка (`--build`).

Где хранятся данные:

- **`.env`** — файл хоста, смонтирован в контейнер. Ключи и настройки, сохранённые из веба,
  пишутся в него же. Без `.env` контейнер не запустится.
- **Ваши персоны и память** — том `vpc_data` (`data/personas/` и память), отдельно от `data/`
  локального запуска. Встроенные персоны — в образе. Чтобы работать с локальными персонами
  и памятью, замените в `docker-compose.yml` `vpc_data:/app/data` на `./data:/app/data` и не
  запускайте бота локально и в Docker одновременно.
- **Модели Hugging Face** — том `hf_cache`. Модель памяти уже в образе; модели книжного
  поиска Арродеса скачиваются при первом обращении.

Особенности:

- **Ollama** берётся с хоста: `http://host.docker.internal:11434`, другой адрес —
  `DOCKER_OLLAMA_URL` в `.env`. `OLLAMA_URL` из `.env` в контейнере не используется:
  `localhost` там — сам контейнер.
- **Часовой пояс** в контейнере — UTC. Задайте `TIMEZONE` в `.env`, иначе напоминания и
  границы суток сдвинутся.
- **Браузера в контейнере нет:** режим управления, веб-чаты и поиск через браузер работают
  только при локальном запуске.
- API в контейнере слушает `0.0.0.0` — иначе до него не дойдёт проброс порта — и проверяет
  имя хоста (`API_ALLOWED_HOSTS`, по умолчанию `localhost`). Предупреждение в логе о привязке
  не к loopback ожидаемо: снаружи API доступен только с `127.0.0.1` хоста.

## Аддоны

Аддон — Python-пакет, который подключается через entry points:

- `virtual_persona.addons` — класс аддона;
- `virtual_persona.personas` — папка с YAML его персон.

Персона включает аддон списком `features.addons`. Аддон добавляет блок в промпт
(`build_context`) и чинит или чистит ответ (`repair`, `postprocess`). Сломанный или
неустановленный аддон пропускается с предупреждением в логе.

**Арродес** — персона-знаток «Lord of Mysteries», отдельный репозиторий: поиск по тексту
книги (векторы, BM25, переранжирование), глоссарий в промпте, ссылки на фрагменты `[ФN]`.
Ставится в тот же Python, что и ядро, после него:

```bash
pip install -e .                          # ядро — первым
pip install -e <папка Арродеса>
```

Книжная база лежит в папке Арродеса, память персоны — в данных ядра. Сборка базы и
проверки — в README Арродеса.

## Тесты

Тесты — скрипты `scripts/test_*.py` (115), без pytest; тесты Арродеса — в его
репозитории. Запуск из корня проекта:

```bash
OLLAMA_URL=http://127.0.0.1:9 python -m scripts.test_computer_control
```

`OLLAMA_URL` на мёртвый порт — чтобы тест не грузил настоящую модель. Каждая проверка
печатает `[OK]` или `[FAIL]`, в конце — итог. Часть скриптов завершается с кодом 0 и при
провалах, поэтому смотрите на `[FAIL]` в выводе, а не на код возврата. Для Telegram-тестов
нужен `python-telegram-bot`, для части тестов браузера — Node.js и Playwright с Chromium.

## Зависимости

**Python.** В `pyproject.toml` — диапазоны версий: снизу то, на чём проект проверен, сверху —
до следующей мажорной. `requirements.txt` — lock-файл с точными версиями для всех платформ,
его собирает [uv](https://docs.astral.sh/uv/) из `pyproject.toml`. Чтобы обновить пакеты,
поправьте диапазоны, пересоберите lock командой из шапки `requirements.txt` (с `--upgrade` —
до новейших версий в диапазонах) и прогоните тесты. Голосовая активация на компьютере —
необязательный набор: `pip install -e ".[voice]"` (sherpa-onnx, sounddevice) — в тот же Python
или venv, в котором запускается ядро.

**Веб и панель.** Точные версии — в `web/package-lock.json` и `desktop/package-lock.json`.
`npm ci` ставит ровно их, `npm install` может обновить lock.
