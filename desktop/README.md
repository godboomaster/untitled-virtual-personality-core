# Панель Virtual Persona (desktop/)

Значок в трее (строка меню macOS, область уведомлений Windows) и окно-панель
по клику. Панель запускает, перезапускает и останавливает бэкенд бота
(`python -m app.main api`) и веб-интерфейс (`vite` из `web/`), показывает их
состояние, браузеры бота, Ollama, свободную память и живой лог, а ещё умеет
открыть браузер бота видимым, чтобы войти в веб-чаты или пройти капчу.

В трее — логотип с белой заливкой призрака и скорлупы, чёрными глазами,
обводкой и трещинами (`design/branding/118-white-filled-ghost-shell.png`).
На macOS размер — 24 pt (48 px для Retina). Цвета и прозрачный фон сохраняются
во всех темах; состояние бота видно в подсказке и панели. В веб-интерфейсе
та же версия используется в боковой панели (48 px), вкладке браузера и уведомлениях.

Tauri 2: Rust (`src-tauri/`) + React (`src/`). Окно — системный WebView
(WKWebView / WebView2), своего Chromium нет.

## Что делает

- **Запуск/остановка/перезапуск.** Остановка штатная: `POST /api/system/shutdown`,
  дальше uvicorn гасит сервер и браузер бота, как по Ctrl+C. Если бэкенд не ответил
  за 25 с — SIGTERM, затем SIGKILL (на Windows `taskkill /T /F`).
- **Бот, запущенный в терминале,** панель видит как «запущен вне панели». Его тоже
  можно остановить или перезапустить: после перезапуска он работает уже под панелью.
- **Падение:** причина и последняя строка вывода видны в панели. Автоперезапуск — не
  больше 3 раз за 10 минут, дальше панель ждёт пользователя.
- **Лог** — в `logs/backend-ГГГГ-ММ-ДД.log` и `logs/web-…` в корне проекта, хранится
  14 дней. Опросы самой панели (`/api/health` и др.) в файл не пишутся. В окне — лента
  `/api/logs`, а если бэкенд упал — последние строки вывода процесса с traceback.
- **Браузер бота** — rescue пула H (как реплика «почини браузер»): веб-чаты
  перезапускаются в видимом окне. «Готово» завершает rescue по тому же правилу, что
  реплика «готово».
- **Голосовая активация** («Коннор, какая погода?») — слушает панель, а не бот:
  «Слушать имя» в меню трея или кнопка в окне. Слушатель — отдельный процесс панели
  (`python -m app.voice.wake_listener --status`, тот же Python, что у бота, с набором
  `.[voice]`), поэтому микрофон принадлежит «Virtual Persona». Слушание идёт и при
  выключенном боте, бот нужен только для ответа. Боту, запущенному панелью, передаётся
  `WAKE_LISTEN=0`; бот из терминала уступает микрофон слушателю панели, пока тот раз в
  секунду сообщает ему о себе (`/api/voice/wake/report`). В окне видно, что происходит:
  слушает и какие имена, ждёт бота, пауза на голосовой чат веба, нет доступа к
  микрофону или нет модулей (с командой `pip`). Упал — перезапуск, не больше 3 раз за
  10 минут. Лог — `logs/voice-…`. Пока слушание не переключали, панель следует
  `WAKE_LISTEN` из `.env`. «Язык речи» в окне — русский и английский (по умолчанию), только
  русский или только английский: панель передаёт слушателю `WAKE_LANG` и перезапускает его
  (модели грузятся при запуске); не выбирали — как `WAKE_LANG` в `.env`.
  Разговор у портрета: слушатель запущен с `--portrait`; прозвучало имя, а чат этой персоны
  в вебе на этом компьютере не открыт (ядро отдаёт открытые чаты в ответе на `/report`) —
  панель ставит её портрет на стол, не трогая «на столе» в настройках, и дальше с ней
  говорят без имени, пока не замолчат на `WAKE_CONVERSE_SEC` (60 с), не скажут «хватит» или
  «пока». Фраза уходит, когда человек молчит `WAKE_TALK_PAUSE_SEC` (5 с): задумался посреди
  фразы — продолжение допишется к ней. Что вы говорите, видно облачком сбоку по ходу речи; значок микрофона у головы —
  разговор идёт, клик по нему — конец (`end` слушателю в stdin). Назвали в разговоре другую
  персону — её портрет встаёт рядом (своё окно `portrait-<id>`, на время разговора), слушает
  теперь она, прежняя ждёт, пока её не назовут снова. «Убрать из разговора» в меню её портрета
  — разговор дальше без неё (`leave <id>`). Персону можно перебить: пока она отвечает голосом,
  слушатель узнаёт её голос в микрофоне по словам ответа, а ваши слова поверх него (две-три,
  имя другой персоны, «подожди», «хватит») — она замолкает, реплика на портрете обрывается.
- **Портрет на рабочем столе** — «Портрет на рабочем столе» в меню трея или блок с тем же
  названием в окне панели (показать или убрать, выбрать персону). В боковой панели чата
  над «Досье» — «Аватар поверх окон»: показывает нативный аватар выбранной персоны,
  повторное нажатие убирает его. Для кнопки нужны запущенные актуальные ядро и панель
  в трее; загружать листы портрета необязательно — есть облик из «Комнаты».
  Панель сообщает состояние ядру через `/api/desktop/portrait/report`, поэтому кнопка
  видит и изменения из трея. Сам портрет работает и без запущенного
  бота: атласы и имена персон панель тогда читает прямо из папки данных ядра (`VPC_DATA_DIR`,
  иначе `data/` репозитория). Живой портрет
  персоны (тот же, что в голосовом режиме веба) в прозрачном окне без рамки поверх всех окон:
  смотрит на курсор, где бы он ни был, моргает. Мимо фигуры окно мышь не ловит — клики уходят
  окну под ним; над фигурой клик — погладить (глаза закрыты, голова под руку, сердечко; ядру —
  сигнал `pet`: персона узнает, если в досье включена «Реакция на тычки», не чаще раза в
  15 минут), зажать и потянуть — переставить, колёсико — размер, правая кнопка — выбрать
  персону, включить или выключить облачка и поле для сообщений, убрать портрет. Персона
  говорит — над головой облачко с репликой: ответ в чате, откуда бы ни писали (веб, телефон,
  голос, поле у портрета), и фоновые сообщения. Реплики панель ждёт долгим опросом ленты
  реплик ядра `/api/said`. Слова в облачке появляются по одному; длинная реплика идёт по частям под размер облачка, одна за другой,
  пока персона не договорит (курсор над облачком или вас нет — часть ждёт); клик по облачку —
  следующая часть, по последней — чат в вебе. Сбоку от головы — поле для сообщений (с той
  стороны, где на экране больше места: голова справа — поле слева, и наоборот): Enter
  отправляет реплику персоне портрета (как из веба), пока ждёт ответа — персона «думает».
  Поле видно, пока курсор над персонажем или над полем; курсор ушёл — поле исчезает через
  3 секунды после последнего нажатия в нём; набранный текст остаётся до следующего наведения.
  Кнопка чата размещается независимо от головы: её появление и скрытие у края экрана
  не сдвигают аватар. При захвате, падении и прыжке кнопка раскрытия чата и плеер
  скрыты; музыка продолжает играть. После приземления снова действует обычное
  появление при наведении.
  Голову можно задвинуть за любой край экрана, и за верх тоже (на экране остаётся хотя бы
  треть её) — поле и облачко остаются на видимой части: поле не ниже 10 px от низа экрана,
  облачко не выше верха (опускается на голову) и не за боками; пока портрет на экране
  целиком, они на своих местах у головы. Перетаскивает окно сама панель, пока зажата кнопка
  мыши: системное перетаскивание macOS не пускает окна выше строки меню (по той же причине
  панель отключает это ограничение у своих окон — `platform::allow_offscreen`).
  При броске отскок от боков и потолка учитывает полный размер спрайта анимации,
  включая кадры шире головы; панель плеера на границы полёта не влияет.
  Окно берёт клавиатуру только после щелчка в поле; Esc или переход в другое окно — отдаёт.
  Спит — глаза закрыты, «z» у макушки: когда вас нет у компьютера (5 минут без мыши
  и клавиатуры), когда персона спит в «Комнате», а если ядро этого не знает — с 0 до 7 часов;
  погладили — просыпается и 5 минут после последнего касания не спит, потом засыпает снова.
  Попадание по фигуре — по прозрачности кадра: панель сообщает окну, где курсор
  (`portrait.rs`), страница (`src/portrait/`) отвечает, над фигурой ли он. Энергия: курсор
  сверяется раз в 33 мс, только пока он у окна, вдали — раз в 100 мс, когда вас нет — раз в
  250 мс; кадры взгляда не крутятся, пока взгляд на месте; «дыхание» — ступеньками (плавная
  анимация окна поверх всех окон держала WindowServer на ~35% процессора). Чей портрет, где и
  какого размера — `portrait.json` рядом с `config.json`; атласы последней загрузки — в кэше
  приложения, так что без бота портрет остаётся на столе, а заново качаются, только когда
  портрет правили. Персон с портретом, спит ли каждая и когда портрет правили, ядро отдаёт
  `GET /api/portraits`. Прозрачному окну на macOS нужен `macOSPrivateApi` (включён в
  `tauri.conf.json`; в App Store с ним не пускают).
- **Выход** из панели останавливает то, что запустила она сама, и слушатель имени;
  бот из терминала продолжает работать.

Параметры бэкенда (порт `API_PORT`, хост `API_HOST`, `API_TOKEN`, `OLLAMA_URL`) панель
читает из `.env` / `.env.config` проекта по тем же правилам, что `app/main.py`.

## Настройки

Шестерёнка в панели. Файл — `config.json` в папке настроек приложения:

- macOS: `~/Library/Application Support/dev.virtualpersona.panel/`
- Windows: `%APPDATA%\dev.virtualpersona.panel\`

Папка проекта по умолчанию — та, из которой собрана панель. Python, если не задан,
ищется сам: `.venv`/`venv` проекта → `PATH` login-shell → обычные места установки. Берётся
первый, где импортируются `fastapi`, `uvicorn` и `dotenv`, и найденный путь запоминается.
Node.js нужен для веб-интерфейса, его в `web/` запускают напрямую
(`node web/node_modules/vite/bin/vite.js`) — сначала выполните `npm ci` в `web/`.

## Отдельный трей робота

Трей Raspberry Pi — часть этой же панели, включается только явным аргументом
`--robot`. В обычной панели нет ни меню, ни блока робота; подключённая Pi сама
их не включает. Оба режима можно держать открытыми одновременно: у робота своя
блокировка второй копии, настройки и запись автозапуска. На macOS возле значка
трея робота стоит `Pi`.

После сборки на macOS откройте [**`vpc-robot/robot.command`**](../../vpc-robot/robot.command)
двойным щелчком. Исходники интерфейса и SSH-контроллера находятся в соседнем
репозитории `vpc-robot/desktop/`; общая панель подключает их при сборке.
Для разработки обе папки держат рядом: `virtual-persona-core/` и `vpc-robot/`.
Для установленного приложения:

```sh
open -n -a 'Virtual Persona' --args --robot
```

Разработка из `desktop/`: `npm run robot`. На Windows готовый исполняемый файл
запускается как `vpc-panel.exe --robot`.

В меню трея и в панели доступны:

- **Запустить службу робота** — подключиться по SSH и запустить пользовательскую службу
  `vpc-robot.service` на Pi. Токен и адрес ядра служба читает из своего `device.env`.
- **Запустить в проекте** — запустить ядро и веб-интерфейс по настройкам панели,
  дождаться ответа ядра, запустить службу Pi и дождаться появления именно её ID
  в `/api/devices` (до 45 секунд). Уже работающие процессы повторно не запускаются.
- **Остановить службу** — остановить клиент VPC, оставив Pi включённой.
- **Выключить Raspberry Pi** — сначала остановить клиент, затем по SSH вызвать
  установленный на Pi `power.PowerController` в пользовательской службе systemd.
  Используются те же проверки и существующее разрешение `logind`, что у команды
  «выключи себя» в чате; `sudo` и ввод пароля не нужны. При подтверждении Pi
  планирует штатное выключение через 10 секунд. Если остановка не удалась,
  выключение не посылается. Панель проверяет подтверждение планирования;
  отключение питания от адаптера она не выполняет.

Питание выключенной платы нужно подать физически: SSH не может включить Pi без
питания. Закрытие трея не выключает Pi и не останавливает её службу.

В блоке **«Робот → Подключение»** задаются хост, пользователь, порт, необязательный
путь к ключу и ID устройства в ядре. Начальные значения — `pi@zhelezyaka.local:22`
и `vpc-pi`; они соответствуют примеру настройки в
[vpc-robot](../../vpc-robot/README.md#автозапуск-клиента). Служба должна быть установлена
по инструкции этого репозитория. Первое открытие трея не запускает ядро и не включает
микрофон; настройки проекта берутся из обычной панели, затем сохраняются отдельно.

SSH работает без запросов пароля: нужен ключ (обычный `~/.ssh`, SSH-агент или путь
в настройках) и уже проверенный ключ хоста. Один раз подключитесь обычным
`ssh pi@zhelezyaka.local`, проверьте ключ Pi и настройте вход по ключу.

Для выключения нужен установленный `~/vpc-robot/power.py`, `device.env` с
`VPC_POWEROFF_ENABLED=1` и существующее разрешение `logind` на выключение Pi 4.
Трей загружает окружение из `device.env` средствами systemd и проверяет ответ
того же обработчика, который использует чат. Sudoers и системные права не меняются;
при отказе разрешения команда завершается ошибкой без запроса пароля.
Пароли, ключи и токен API в проект не копируются. При ошибке SSH, разрешения,
службы или регистрации ядра причина видна в панели. Доступность SSH и
подключение к проекту показываются отдельно.

Настройки робота: `robot.json` в каталоге `dev.virtualpersona.panel.robot`
(на macOS — `~/Library/Application Support/dev.virtualpersona.panel.robot/`).
Автозапуск этого режима сохраняет аргумент `--robot` и не меняет автозапуск
обычной панели.

## Сборка

Нужны Node.js и Rust (`rustup`). Проверка интерфейса и Rust-тесты:

```bash
cd desktop
npm ci
npm run build                       # tsc + vite
(cd src-tauri && cargo test)        # в т.ч. жизненный цикл на поддельных бэкенде и слушателе
```

### macOS

```bash
npm run tauri dev                   # разработка: окно с горячей перезагрузкой
npm run build:mac                   # приложение, подписанное постоянным локальным ключом
npm run check:mac                   # целостность .app и совпадение с постоянным ключом
```

Готовое приложение: `src-tauri/target/release/bundle/macos/Virtual Persona.app`.
Перенесите его в «Программы» **до** того, как включать «Открывать панель при входе»:
агент автозапуска запоминает путь к приложению.

Бот, запущенный панелью, работает от её имени. Поэтому macOS один раз спросит
разрешения, которые раньше давались терминалу: папка «Документы», управление другими
приложениями (AppleScript), а при включении «Слушать имя» — микрофон для «Virtual Persona».

Разрешения macOS привязывает к подписи приложения. `tauri build` подписывает его «на
лету»: подпись — хеш файла, у каждой сборки свой, и после любой пересборки macOS
спрашивала бы всё заново. Поэтому `npm run build:mac` после сборки подписывает
приложение своим ключом (`scripts/macos-sign.sh`): самоподписанный, создаётся при первом
запуске в `~/Library/Application Support/dev.virtualpersona.panel/signing/` и годится
только для этого компьютера. Тогда macOS узнаёт приложение по ключу и идентификатору
`dev.virtualpersona.panel`. Если ключ и подпись сохраняются, разрешения продолжают
относиться к новым сборкам. Удаление этой папки уничтожит ключ и потребует заново
выдать разрешения. Для `.dmg`, который ставят на других компьютерах, нужна
подпись разработчика Apple (`signingIdentity` в `tauri.conf.json`).

Перед сборкой закройте панель через **«Выход» в меню трея**: `build:mac` проверяет,
что она остановлена. Для обычного использования собирайте именно `npm run build:mac`.
Прямой `cargo build`, `tauri build` и копирование нового `vpc-panel` внутрь старого
`.app` обходят постоянную подпись; при копировании бинаря нарушается и целостность
пакета. `tauri dev` также не использует эту постоянную подпись. Одинаковое имя
приложения в настройках macOS не означает совпадение подписей.

Если разрешения уже выдавались, но снова появляются запросы или уведомление
«заблокировано при попытке внести изменения в приложения», сначала закройте панель
через меню трея и выполните из `desktop/`:

```sh
npm run sign:mac                    # подписать готовую .app прежним ключом, без пересборки
npm run check:mac
```

Затем откройте ту же `.app` заново. Уже запущенные ею Python и браузер тоже должны
завершиться: macOS относит их запросы к запустившей панели. Для проверки подписи
другой копии: `npm run check:mac -- '/полный/путь/Virtual Persona.app'`.
Если macOS успела сохранить разрешения для временной подписи, может понадобиться
заново добавить исправленную `.app` в соответствующий раздел конфиденциальности.
Уведомление об изменении приложений относится к **«Управлению приложениями»**;
**«Автоматизация»**, **«Универсальный доступ»** и **«Мониторинг ввода»** — отдельные
разрешения. Оно может исходить и от служебного процесса Chrome, запущенного ботом,
при этом macOS показывает имя Virtual Persona.

### Windows

Нужны Rust с MSVC (`rustup default stable-msvc`), Visual Studio Build Tools
(«Разработка классических приложений на C++») и WebView2 (в Windows 11 он уже есть).

```powershell
cd desktop
npm ci
npm run tauri build -- --bundles nsis
```

Установщик: `src-tauri\target\release\bundle\nsis\Virtual Persona_0.1.0_x64-setup.exe`
(ставится для текущего пользователя, без прав администратора). Бэкенд и vite
запускаются без окон консоли. Python ищется так же: `.venv\Scripts\python.exe`,
затем `PATH` (заглушка Microsoft Store пропускается), затем
`%LOCALAPPDATA%\Programs\Python\Python3*`.

## Устройство

| Файл | Что внутри |
|---|---|
| `src-tauri/src/main.rs` | сборка приложения: плагины, трей, окно, команды |
| `src-tauri/src/supervisor.rs` | процессы бэкенда и vite: запуск, остановка, падения, «внешний» процесс |
| `../../vpc-robot/desktop/robot.rs`, `../../vpc-robot/desktop/RobotPanel.tsx` | режим `--robot`: SSH, служба Pi, запуск с проектом и штатное выключение |
| `src-tauri/src/voice.rs` | голосовая активация: слушатель имени — процесс панели, его состояние, перезапуск |
| `src-tauri/src/platform.rs` | различия ОС: группы процессов / taskkill, PID по порту, поиск Python и Node |
| `src-tauri/src/probe.rs` | проверки: `/api/health`, порты, CDP браузеров, Ollama, память |
| `src-tauri/src/logs.rs` | вывод процессов → файлы `logs/` и хвост для панели |
| `src-tauri/src/commands.rs` | команды окна: снимок состояния, действия, настройки |
| `src-tauri/src/tray.rs`, `panel.rs` | значок и меню трея; окно у значка, прячется при потере фокуса |
| `src-tauri/src/portrait.rs` | портрет на рабочем столе: окно, курсор, сквозные клики, место и размер, меню |
| `src/` | интерфейс панели (React) |
| `src/portrait/`, `portrait.html` | страница портрета: движок `web/src/portrait/LivePortrait.tsx`, маска попадания, «погладить» |

Эндпоинты бэкенда для панели — в `app/api/server.py` (раздел «Панель на рабочем
столе»), тест — `scripts/test_desktop_api.py`.
